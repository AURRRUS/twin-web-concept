# Исполнимое ТЗ TWIN_SALES_STORY_R1

## A. Единая логика страницы

Адресат сайта — девелопер и его коммерческая команда. Покупатель недвижимости — пользователь демонстрируемого продукта. Не смешивать адресатов в одном безымянном абзаце.

Последовательность основной страницы: hero → Journey 4 → существующий блок Twin в работе → состав Twin → каналы продаж → три качества → как запускаем → контакты. Сохранить утверждённое позиционирование, существующие разделы и реальные действия. Journey объясняет выбор покупателя; каналы — применение одной основы в продажах; три качества — основания и условия выбора самого Twin; запуск — порядок работы.

Связующий принцип: вопрос покупателя → показанная возможность → применение командой продаж. Внутренние CJM/JTBD используются для построения, сами термины не выводить на сайт.

Текстовые мосты, по одной строке на границе: после Journey «От знакомства с проектом — к обсуждению конкретного лота»; под составом перед каналами «Используйте эту основу во всех каналах продаж»; перед полосой запуска «Как запускаем Twin на проекте». Не создавать отдельные пустые экраны ради этих строк. Не добавлять другие слоганы. Отменённое «Из проекта — в выбор. Из выбора — в продажу» не использовать.

## B. Паттерны и связи

1. Общая сетка: те же левые/правые границы у заголовков, медиа, списка каналов, полосы запуска и формы. Desktop max-width1728px; поля 64px при 1440,80px при 1920,32px при 1280. Ширина<1024 — поля 20px, при 320 —16px. См. токены. Уже принятый hero не переделывать ради новой сетки на desktop.
2. Мотив Сечения: короткая тонкая линия и один бронзовый маркер активной части. В Journey — этап выбора; в каналах — текущий сценарий; в треугольнике — связи аргументов. Это родственные локальные элементы, не одна гигантская фиксированная линия через всю страницу. Не перерисовывать/зеркалить логотип, не добавлять кристаллы ПИН и персонажей LanDocs.
3. Управление вниманием: главный тезис → задача/пояснение → визуальное доказательство → следующий шаг. У каждого блока один главный акцент. Бронза — смысловая часть H2 и активное состояние, не каждый абзац.
4. Ритм: большой продуктовый визуал → существующий функциональный блок и состав → человеческие ситуации каналов → компактный аргумент условий → спокойная полоса запуска → графитовый контакт. Не превращать всю страницу в одинаковые карточки и одинаковый parallax.
5. На мобильном линия становится коротким разделителем и маркером текущего пункта. Не тратить ширину на декоративную вертикальную дорожку.

## C. Основная страница и сравнение

На основной странице показывать ОДИН доработанный Journey 4. Все существующие исходный и варианты 1–6 оставить в режиме ?compare=journey в текущем порядке; вариант 4 там показывает обновлённую реализацию, предыдущая сохранена в резервной ветке. Никакой вариант не удалять из кода в этом пакете.

Ссылки существующих #journey-original и #journey-variant-1…6 должны приводить к нужной сцене сравнения: при таком hash автоматически включить режим сравнения, сохранив query и hash; не отправлять человека к отсутствующему элементу. #journey-variant-4 на основной странице допустим как прямой вход в выбранный Journey. Для остальных hash переадресация на тот же URL с compare=journey через replaceState до измерения геометрии, без reload-loop. Прямые ссылки на сцены 0–3 сохранить, проверить конфликт fragment/кнопок.

В сравнении компактное меню Исходный / 1 / 2 / 3 / 4 / 5 / 6 и «К сравнению». Публичную основную навигацию не засорять техническим меню вариантов; ссылку сравнения предоставить владельцу в отчёте. На мобильном основной сайт также содержит один Journey. Режим сравнения доступен и там, но не является обычным сценарием клиента.

## I. Инженерные ограничения

Не менять стек. Использовать существующий motion-слой, без новых библиотек для каждого блока. HTML-тексты и controls — DOM. Уникальные ID/refs, локальныеCSS, общие типизированные данные. Не разбрасывать одинаковые строки по нескольким файлам. Никаких глобальных обработчиков, управляющих первым найденным Journey.

Scroll-геометрия после fonts.ready/images и resize; изображения с width/height, srcset/разумными размерами. Не подгружать все неактивные сравнения на обычном сайте. На странице сравнения соседние медиа готовить до входа, без повторной загрузки одинаковогоURL. Observer/RAF прекращаются вне активной области и очищаются при размонтировании. Не добавлять тяжёлые 24 МБ изображений в мобильный initial-load; исходники архива — резерв, не инструкция грузитьPNGвсегда.

Font-face и размеры по TOKENS.json; реальные шрифты приложены. Заголовки без точек, все заголовки — Dewi, нулевойtracking, безscaleX, отрицательного tracking, font-stretch и synthetic bold. Рубрики/маршруты/менюDewi600; body — Inter Tight 450. Существующие логотип/цвета и desktophero сохраняются. Выполнить приёмку и публикацию из 06_ACCEPTANCE.md.
