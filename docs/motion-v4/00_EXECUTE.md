## Что подтверждено

H1 сейчас RF Dewi Expanded400, гарнитура подключена. Назначение файлов однозначно: Regular.ttf→400, Semibold.ttf→600, Bold.ttf→700; font-synthesis:none, font-style:normal. Не подставлять600 для Bold. Текущую гарнитуру не менять. Заголовки без конечных точек, tracking0. Не ставить отрицательный tracking ради вмещения. У абзацев Inter Tight400, tracking0; UI500/600 — реальные веса variable font.

В браузере reduced-motion=false, есть31 data-craft-reveal. После нативной прокрутки к product число ожидающих уменьшилось31→27; четыре элемента product прошли от opacity0 до1. Следовательно механизм не отсутствует: нужна режиссура видимого появления, не ещё один независимый observer. Сохранить один механизм и проверить его работу на живом сайте. Утверждение «всё анимировано» по наличию атрибута не принимается.

## Второй экран: рамка и выбор

Удалить декоративную связь с фасадом: .scene-navigation::before и иные connector-линии, не несущие данных. Не удалять линии треугольника или схему composition.

Desktop-предложение для проверки в реальной компоновке: facade35% вместо38%; margin-left правой зоны−80px; центральная колонка208px, gap24px. Текстовый отступ слева104px от правой зоны даёт24px от полного края фасада. Диагональ фасада ниже перехода заканчивается на80px раньше. Это освобождает ширину правому медиа: примерно624px при1280,720px при1440,840px при1920 с существующими полями. Не назначать проценты вслепую на mobile. Приложен CSS для текущих selectors.

Сохранить пропорции кадра16:9, contain; не обрезать карточку лота и не вытягивать PNG. Площадка медиа не меняет размер между состояниями. Caption и «Развернуть изображение» привязать к её нижней границе. Верх медиа совпадает с началом группы навигации, её три пункта равномерно распределены в этой же высоте. Нет отдельной «плавающей картинки» и искусственных пустых полей.

Выбранный пункт: название и номер бронзовые#8B6138, описание графитовое; неактивные названия#7A838B, описания#66717A. При переключении180ms color и240ms background. Лёгкая бронзовая поверхность только у выбранной строки, без свечения, тени и подъёма. Вертикальная бронзовая черта и маленькая отметка рядом с номером дают ясный выбор. Не создавать fake arrows к случайным этажам. Сохранять aria-pressed и Enter/Space. Заголовок и описание — отдельные block-строки. Все3 названия видны всегда.

## Сцена треугольника: сначала конфликт, затем ответ

Сохранить слова «Быстро», «Доступно» и третью меняющуюся строку как главный типографический мотив. В подписи изменить порядок: сначала «Обычно предлагают выбрать два.», ниже крупнее «В Twin сходятся все три»; ответ появляется при замыкании третьей стороны. Не подавать обычную рыночную дилемму как вывод после нашего ответа.

На desktop саму композицию Delivery поместить в отдельную sticky-обёртку; стартовая длина host230svh, panel100svh. Последовательность шагов запуска остаётся ПОСЛЕ host обычным потоком. Нельзя растянуть всю delivery со steps внутри sticky. Если композиция не помещается по реальному fit (включая шрифт), использовать native flow и выполнить только появление, без обрезки и скрытия текста. Mobile/reduced-motion — все данные сразу, слова «Качественно · Эффектно · Эффективно» видимы статически, треугольник полностью замкнут.

| 0–.14 | Первая сторона и её вершина плавно проявляются |

В SVG у каждого pathLength1, stroke-dasharray1, dashoffset=1−соответствующий edgeProgress. Глубокий бронзовый акцент только на завершении, не неон и не светящийся след. Длины и положения контура сохраняются. Удалить старый короткий draw-edge240ms и observer .delivery.in-view для тех же paths. Смена слов управляется P, не setInterval/autoplay и не выдуманным таймером после входа.

Внутри типографической строки зарезервировать ширину самого длинного слова; строки и окружающий блок не двигаются. Во второй фазе не крутить весь заголовок — только вставка «ив» и сдвиг «но» на её реальную ширину. Font glyph width измерить после document.fonts.ready, никаких чисел из другой гарнитуры. У третьей вершины синхронно менять подпись, а остальные два условия всегда остаются «Быстро» и «Доступно». Для screen reader один статический полный текст, без ежекратного aria-live.

Приложены чистая функция deliveryFrame и React-компонент строки; интегрировать в существующий Delivery.tsx и существующий scroll lifecycle. Значения привязать к DOM через CSS-переменные; setState на каждый rAF только для числового прогресса всего приложения не использовать. Вынести word-узел локально или обновлять ref. Один P, один рендер состояния; обычный scrollTop не перехватывать. Обратная прокрутка восстанавливает состояние, быстрый проход не создаёт очередь.

## Появления остальной страницы

Один существующий initCraftReveals. Его800ms fade+20px не заменяет разные пространственные роли. Product: заголовок через вертикальную маску24px, пояснение opacity/Y12px с задержкой100ms, workspace цельным предметом Y24px/900ms с задержкой180ms. Composition: центр opacity/Y16px, пары боковых узлов последовательно120/220/320ms и соответствующие связи; не двигать всю схему целиком одновременно. Channels: заголовок/табы читаются сразу при входе, изображение отдельной раскрывающей маской900ms; переключения tabs не запускают entrance заново. Delivery управляется собственной сценой и исключён из общего observer. Contact: текст720ms, форма840ms с задержкой120ms. У одного узла не должно быть двух animation-driver.

Trigger для входа — top узла на85% viewport. Предыдущие анимации уже показанных блоков не сбрасывать на opacity0. Через deep-link/фокус открывать контент сразу. При JS failure/reduced-motion всё видно. Не делать mandatory screenshot/video deliverable. Проверять вход каждого блока на реальной медленной прокрутке; отмечать начало, середину и финал в рабочем браузере. Это внутреннее выполнение, не этап согласования с владельцем.

Проверить1440×900,1366×768,1280×800,1920×1080 и390×844; typography exact file/weight, отсутствие clipping/двойной пунктуации, навигацию, геометрию медиа. Числа цены/срока не менять и не анимировать как факты промежуточными значениями. Не добавлять утверждение о доказанной коммерческой эффективности — это презентационное слово, не измеренный KPI.
