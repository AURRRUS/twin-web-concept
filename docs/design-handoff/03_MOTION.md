# Хореография Twin

Применить метод code-motion: один источник progress, состояние вычисляется по абсолютному progress. Это исполнимая постановка, но не готовый протестированный модуль. Числа — стартовые настройки для реализации.

## Одна физика

Скролл управляет раскрытием, заголовок предшествует описанию, визуал вступает последним. Появившийся текст неподвижен во время чтения. Без bounce, elastic, вращения листов и тяжёлых теней. Не объединять три самостоятельных элемента в один общий fade-wrapper.

В существующем stack использовать уже установленный motion-инструмент. Если есть GSAP ScrollTrigger — одна timeline для второго экрана; не устанавливать параллельно Lenis и другие smooth-scroll драйверы без нужды. Нативный scroll не перехватывать через wheel preventDefault. Не добавлять искусственную инерцию всей странице ради слова «премиум».

## Обычные разделы: короткий каскад

Для секции, кроме hero и двух специальных сцен: начало, когда верх смысловой группы достигает 82% viewport. Проигрывание один раз; при возвращении контент остаётся видимым. Это короткий локальный reveal по времени, а не обязательный pin.

| Элемент | Старт относительно trigger | Длительность | Начало → конец |
|---|---:|---:|---|
| Eyebrow | 0ms | 420ms | opacity 0→1, Y 6→0px |
| Заголовок | 80ms | 620ms | маска inset снизу 100→0%, Y 18→0px |
| Описание | 250ms | 600ms | opacity 0→1, Y 12→0px |
| Визуал | 420ms | 900ms | opacity 0→1 за первые 180ms, scale 1.045→1, Y -24→0px |
| Карточки / факты | 400ms + 90ms*index | 600ms | opacity 0→1, Y 14→0px |

Easing reveal: cubic-bezier(.22,1,.36,1). Медиа движется внутри своего зарезервированного пространства. Не перекрывать заголовки увеличенным фото. Не применять одновременно общий reveal родителя и независимый reveal ребёнка. «Единая цифровая основа» — без нового сложного parallax; четыре канала — stagger 90ms, без четырёх независимых pinned-сцен.

Hero при загрузке: фотография доступна сразу. H1 появляется максимум за 500ms без заметного перемещения; описание на 140ms позже, каналы на 280ms позже, CTA на 380ms. Не скрывать CTA на секунды, не делать бесконечную смену каналов. Последовательное раскрытие слов каналов допустимо с шагом 80ms, при заранее зарезервированном месте всех четырёх.

## Второй экран: листы укладываются в одно рабочее пространство

Desktop >=1280px и viewport height >=760px. Sticky height 100svh, длина секции 380svh; полезный scroll = высота секции минус высота sticky. Progress p = clamp((scrollY - sectionStart) / usefulScroll, 0, 1). После resize пересчитать геометрию. Не привязывать к одному щелчку колеса.

При подходе к секции отдельно раскрыть первое состояние: h2 → body → image, по короткому каскаду выше. На начале pin состояние «Проект» уже полностью собрано. Не начинать закрепление пустым экраном.

| Progress p | Состояние |
|---|---|
| 0–0.20 | Проект, чтение |
| 0.20–0.45 | Проект → Пространство, каскад |
| 0.45–0.60 | Пространство, чтение |
| 0.60–0.85 | Пространство → Лот, каскад |
| 0.85–1 | Лот, чтение; штатный выход |

Каждый переход имеет локальный q=(p-start)/(end-start). Ранжирование слоёв постоянно: project z1, space z2, lot z3. Ниже описаны local q-интервалы, а не секунды.

| q | Действие |
|---|---|
| 0–0.12 | Старые h2/body исчезают, Y 0→-8px, opacity 1→0 |
| 0.08–0.24 | Активный пункт и бронзовый маркер переходят к новой главе |
| 0.12–0.40 | Новый eyebrow и h2 раскрываются: Y 18→0px, маска снизу 100→0% |
| 0.32–0.62 | Новое описание opacity 0→1, Y 12→0px |
| 0.48–1 | Новый медиаслой поверх старого: scale 1.08→1, Y -48→0px |
| 0.48–0.62 | Opacity нового медиаслоя 0→1; старая картинка остаётся под ним |

В текстовых слотах резервировать высоту самого высокого текста из трёх состояний после реальной загрузки шрифтов и на текущей ширине. Новые строки не сдвигают медиа и навигацию. Маску делать на отдельной обёртке, не обрезающей выносные элементы букв.

Лист — весь слой медиа, не только zoom картинки внутри неподвижной рамки. Transform-origin center center, общий clipping viewport. Последовательность даёт ощущение, что увеличенный лист находится ближе и мягко опускается сверху на место. Предыдущий слой не исчезает раньше, чем новый его покрыл. Без белой вспышки, flip, тяжёлой тени, blur и перспективного наклона.

Внутри scrub-перехода easing smoothstep t*t*(3-2*t), каждое значение вычислять из p; отдельные CSS transitions на те же свойства отключить. Допустим сглаженный progress с запаздыванием не более ~0.25s, но остановка не должна продолжать самостоятельный длинный ролик. Обратный scroll симметрично раскрывает прежний слой, текст и навигацию. Не назначать display:none по ненадёжным односторонним callback.

Клик по пункту навигации прокручивает к середине соответствующего hold-диапазона (p .10/.525/.925). Реальные button, keyboard focus, aria-current для выбранного состояния; не объявлять изменение главы через aria-live на каждом кадре. Полный смысловой текст доступен в DOM. Все три картинки декодировать до начала переходов; при ошибке показать подпись и доступный путь к demo, не пустую сцену.

## Треугольник и изменение слова

Desktop: короткая sticky-сцена 200svh (100svh usefulScroll), только при height >=760px. Переменная p отдельная, не progress второго экрана. Не вводить дополнительный длинный pin в каждом разделе.

| p | Содержание |
|---|---|
| 0–.12 | «Обычно предлагают выбрать два», вступление |
| .08–.25 | «В Twin сходятся все три качества» |
| .15–.35 | Две стороны треугольника и подписи срока/стоимости |
| .30–.50 | Третья сторона замыкается, модель и демопревью проявляются |
| .50–.64 | Собранное состояние: Быстро · Доступно · Эффектно |
| .64–.84 | Эффектно → Эффективно |
| .84–1 | Финальный hold, CTA доступен |

Две стороны в начале — постановка привычного ограничения; третья завершает смысл «все три». Stroke-dashoffset для линии, исходные изображения — DOM img, не canvas-перерисовка. Значения 3 месяца/5 млн ₽ не анимировать счётчиком с вымышленными промежуточными числами.

Слово разложить на «Эффект» + «ив» + «но». На p .64→.84 вставка «ив» раскрывается шириной от 0 до измеренной после fonts.ready и opacity 0→1; суффикс «но» плавно сдвигается. Внешний слот сразу равен ширине «Эффективно», поэтому соседние слова не скачут. В DOM accessibility label полное выбранное слово, технические spans aria-hidden. При обратном scroll вставка убирается. Не заменять всё слово грубым crossfade и не включать предыдущую версию «Качественно»: актуальное решение — Эффектно → Эффективно.

## Mobile, reduced motion, надёжность

- На узких/невысоких экранах: без длинных sticky, нативный поток; три главы видимы последовательно или переключаются доступными tabs. Короткие reveal максимум 350ms, масштаб не более 1.02.
- При prefers-reduced-motion: убрать transforms, masks и pin; все тексты и изображения доступны; треугольник собран, финальное «Эффективно». Не оставлять .opacity-0.
- При JS error/no-JS контент исходно видим. Скрытие включать только после успешной инициализации соответствующей группы.
- Один владелец каждого animated property. Удалить старые observer/reveal/timeline, которые управляют тем же узлом.
- Изменять преимущественно transform/opacity; не читать layout каждого элемента на каждом scroll. Width-вставку слова измерить один раз после fonts.ready и на resize, сам узел малый и изолирован. requestAnimationFrame — не больше одного обновления сцены за кадр.
- Не обещать 60fps по наличию GSAP: проверить реальное поведение, загрузку, быстрый scroll, reverse, anchor navigation, resize и возврат после скрытой вкладки.
