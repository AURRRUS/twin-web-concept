# Композиция и типографика Twin

## Общая система

Фон — текущий светлый фон Twin; графит и бронзу брать из действующих токенов проекта. Не заимствовать палитру ПИН. Бронза — подводки, смысловые части заголовков и активные состояния. Не применять прозрачность ко всему тексту ради «премиальности».

Единая ось контентных разделов: контейнер `min(100% - 2*gutter, 1728px)`, gutter 64px на 1440px, 80px на 1920px, 32px на 1024px, 20px на 390px. Это поля обычных разделов. Второй экран имеет отдельную композицию с фотографией слева и правым визуалом до края.

Смежные текстовые блоки привязывать к общей левой оси. Никаких независимых margin-left «на глаз» у каждого заголовка. Вертикальные интервалы строить из 8px: eyebrow → title 16; title → description 24; description → main content 40. На мобильном 12/20/28px соответственно.

Во всех @font-face задавать одно семейство `Twin Dewi Expanded` с разными font-weight. Inter — отдельное `Twin Inter Tight`. `font-style: normal`, `font-display: swap`, `font-synthesis: none`. Не указывать диапазон весов у статического TTF; не использовать system fallback как финальный результат. Существующий preload обновить на реально используемый файл.

## 1. Header и hero

Меню одной строкой, gap 28px на 1440 / 36px на 1920; без разрядки и капсул. Header action «Обсудить проект» — компактный контурный прямоугольник, radius 4px, height 44px, padding-inline 20px. Существующие якоря сохранить.

H1 на desktop строго две смысловые строки из JSON. Не разрывать «инфраструктура продаж» ради декоративной лестницы. На узком экране разрешить естественные переносы; не удерживать desktop nowrap.

Группа H1 + описание + CTA: начальная верхняя позиция 20svh от верха viewport, при этом не ближе 40px от низа header. Ключевой критерий — вся группа помещается до значимого контура здания с запасом 32px. Уточнить вертикальную позицию по исходной фотографии, не растягивать hero за пределы одного экрана ради отступа.

Описание — две строки смысла и отдельная строка каналов из JSON. Это выбранный для проверки вариант владельца; сохранить все четыре канала. На 1440 строка каналов Inter20 помещается в ширину 1100px; не выравнивать её случайными пробелами. CTA на 28px ниже последней строки. Hero action только «Посмотреть Twin». Фото чистое, никаких белых/молочных overlay.

## 2. Второй экран: Проект → Пространство → Лот

Опираться на journey-composition.png. На desktop >=1280px: левая фотография 29% ширины viewport, на всю высоту сцены; правая область 71%. Верхний текст в правой области с отступом 40px слева на 1440 / 56px на 1920, верх 48px. H2 + описание занимают общую широкую ось; максимальная ширина описания 900px. Длинный eyebrow может переноситься на две строки, не уменьшать его до нечитаемого размера.

Ниже — навигация шириной 190px на 1440 / 220px на 1920, затем gap 24/32px, затем медиа до правого края viewport. Верх медиазоны и навигации выровнен. Фото слева без линий и стрелок. Навигация без бежевого фона: короткая бронзовая вертикаль у активного пункта, заголовок графитовый, описание самостоятельным блоком. Неактивный текст остаётся читаемым, минимум контраста 4.5:1 для обычного текста.

Правое изображение — главный материал сцены, не маленькая фотография в карточке. Общая устойчивая сцена, без device-рамки, псевдообъёмного наклона и тени. Соотношение исходников 16:9; допускается согласованный viewport около 16:10 только с проверкой сохранности UI. Не растягивать изображения. AI-макет показывает кроп; он не разрешает удалять важные данные/управление с оригинала. Если весь интерфейс нужен, показывать оригинал целиком в 16:9. Поверх raster UI не имитировать работающие кнопки.

На <=1279px убрать длинный pin: текст, горизонтальная навигация с переносом, медиа нормальной ширины. На мобильном левое декоративное фото не отнимает весь экран; допускается убрать его, сохранив три продуктовых изображения и весь смысловой текст.

## 3–5. Двойник, основа, каналы

Twin в работе: область под готовый цифровой двойник. Сохранять текущий рабочий переход, пока сам модуль не предоставлен. Статичную картинку не объявлять готовым двойником; показать этот пункт как зависимость в отчёте.

Единая цифровая основа: сохранить действующие внутренние карточки и их содержимое. Заголовок, описание и существующие карточки привести к общей сетке; motion ограничить мягкой последовательностью появления.

Четыре канала: новые изображения должны показывать конкретное действие: сайт — интерфейс выбора на сайте; дистанционно — совместный показ с менеджером; агенты — рабочий интерфейс подбора/обмена; офис продаж — демонстрация на большом экране с менеджером и покупателем. Единый свет и характер проекта. Не подменять четыре сценария четырьмя несвязанными фото красивых интерьеров. Генерация этих изображений в текущий пакет не входит: сохранить существующие до отдельной замены.

## 6. Три качества

Использовать triangle-direction.png как направление, а не копировать толстые буквы из растра. Верхняя иерархия: «Обычно предлагают выбрать два» → «В Twin сходятся все три качества» → «Быстро · Доступно · Эффектно».

Факты 3 месяца и в среднем 5 млн ₽ сохранены с текущего экрана; не превращать их в гарантированный срок/фиксированную цену. Подписи сохранить. Архитектурная модель — исходный ассет, не её AI-перерисовка из макета. Линия треугольника тонкая, узлы 6px, без светящихся шаров. Плашки-капсулы удалить.

Три смысловые группы должны соответствовать трём вершинам: срок ближе к верхней, стоимость к нижней левой, демонстрация к нижней правой. Если расположение групп из макета не даёт ясной связи, приоритет смысловому соответствию, а не буквальной копии растра. Не рисовать дополнительные стрелки.

Справа один доступный переход «Посмотреть Twin» на действующее demo: превью и подпись образуют одну ссылку. Без значка Play, если это не запуск видео. Текстовая ссылка с бронзовым подчёркиванием и стрелкой; никаких больших коричневых батонов. Размер активной области минимум 44px по высоте, фокус видимый.

## 7. Финал и переносы

Сохранить действующий заголовок и текст контакта, убрать точки в конце заголовков. Для текста «Посмотрите, как Twin может работать на вашем проекте» использовать неразрывные группы «как Twin» и «на вашем»; не запрещать перенос всего длинного абзаца. Управлять шириной и смысловыми строками, а не россыпью <br> на всех разрешениях.

Во всех H1–H6, CTA и коротких подводках проверить висячие односимвольные предлоги/союзы. Неразрывные пробелы только в коротких связанных группах; длинные nowrap-фразы не должны создавать горизонтальный overflow.
