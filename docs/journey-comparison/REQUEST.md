ОБЩЕЕ СОДЕРЖАНИЕ

Все три новых варианта реализовать полностью:
Проект → Корпус → Этаж → Лот.

Во всех вариантах использовать одинаковые существующие тексты
и четыре утверждённых изображения из FINAL R2.
Это сравнение дизайна и взаимодействия, а не разных текстов.

Заголовки:
— Проект: «Покажите, что делает / проект ценным»
— Корпус: «Раскройте преимущества / каждого корпуса»
— Этаж: «Упростите выбор / подходящего лота»
— Лот: «Дайте почувствовать / пространство лота»

Знак / — смысловой перенос, не печатный символ.
Вторая смысловая часть бронзовая.

Сохранить правильное соответствие:
Проект — окружение и инфраструктура;
Корпус — расположение корпусов и выбор этажа;
Этаж — план целого этажа с доступными лотами;
Лот — конкретный апартамент, его пространство, планировка и вид.

ТИПОГРАФИКА

Использовать реальные файлы бренда:
— H2: RFDewiExpanded-Black.ttf, 900;
— названия пунктов: RFDewiExpanded-Semibold.ttf, 600;
— прочие заголовки внутри вариантов: Dewi Bold 700;

  letter-spacing 0.015em.

Dewi: tracking 0, нормальные пропорции, без scaleX
и искусственного утолщения другим файлом.

Кегли подобрать под композицию и доступную ширину:
заголовок должен уверенно читаться, изображение оставаться крупным.
Не копировать чрезмерный размер из текущего Journey автоматически.
Не уменьшать весь интерфейс ради одной строки.

Точки в конце заголовков запрещены.
Короткие предлоги и союзы связывать со следующим словом.
Не допускать склеивания слов между span.

ВАРИАНТ 1 — «ДВА МАСШТАБА»

Трёхчастная композиция:
— слева крупный вертикальный фасад, ориентир 21% ширины;
— в центре компактная вертикальная навигация, около 16%;
— справа заголовок, описание и главный визуал, около 63%.

Проценты — стартовые пропорции; учитывать реальные поля и gap.

Фасад остаётся атмосферным контекстом и сохраняется
при смене четырёх состояний. Без стрелок и лишних движений.

Навигация:
четыре названия, тонкая вертикальная линия, активный маркер.
Пояснение показывается только у активного пункта.
Под сменяемое пояснение резервируется место:
остальные пункты не должны прыгать.

Заголовок и описание находятся НАД правым изображением,
в пределах его колонки. Не растягивать заголовок поверх навигации.

Главный фокус — демонстрация продукта справа.

ВАРИАНТ 2 — «ОДНО ОКНО В ПРОЕКТ»

Слева узкая архитектурная полоса фасада:
ориентир 9–12% ширины, без отдельной навигационной колонки.

В основной области:
— сверху горизонтальный маршрут из четырёх состояний;
— ниже заголовок активной сцены и две строки описания;
— ниже одно большое окно демонстрации;
— спокойный счётчик текущего состояния.

Позиция и размер окна остаются стабильными во всех состояниях.
Заголовок и описание тоже имеют зарезервированную область,
чтобы смена текста не двигала изображение.

Здесь важны крупный продуктовый визуал
и ощущение единой системы с последовательным приближением.

ВАРИАНТ 3 — «ЧЕТЫРЕ ГЛАВЫ»

Четыре последовательные сцены в естественном потоке страницы.
Не копировать сюда длинный pin-трек первых двух вариантов.
Каждая глава получает композицию по содержанию:

Проект:
заголовок в верхней левой области, описание справа,
ниже широкий панорамный визуал.

Корпус:
текст слева, крупный визуал выбора корпуса справа.

Этаж:
компактный текст слева, максимально крупный и читаемый
план этажа справа.

Лот:
крупный визуал пространства слева, текст справа.

На desktop справа — узкий указатель четырёх глав.
Он действует только в пределах этого варианта,
показывает реально видимую главу и позволяет перейти к другой.

Сцены появляются последовательно при прокрутке.
Для первого сравнения использовать движение и маски
без сложной перестройки геометрии между главами.
Дать каждой сцене достаточное время и место для чтения.

ИЗОБРАЖЕНИЯ

Макеты imagegen не вставлять вместо HTML.
Не брать из них перерисованные планы, цифры, цены и подписи.

Использовать существующие утверждённые исходники:
геометрию, помещения и содержащиеся в них данные не менять.

Макеты предлагают более чистую демонстрацию продукта.
Если для этого нужны отдельные кадрирования:
— делать их неразрушающе, отдельно от оригиналов;
— сохранять ключевое содержание;
— для этажа сохранять полный план, выбранный лот и контекст;
— не растягивать и не обрезать важные части ради заполнения рамки.

Если существующее изображение нельзя аккуратно привести
к композиции без перерисовки, показать его целиком.
Не генерировать новые изображения в этом задании.

Действие «Развернуть изображение» открывает исходник
в доступном диалоге с закрытием по Escape и возвратом фокуса.
Кнопки внутри растровой иллюстрации не выдавать
за работающие элементы внешнего сайта.

ПРОКРУТКА ВАРИАНТОВ 1 И 2

Все четыре состояния доступны при прокрутке вниз и обратно.
Повторный вход работает с обеих сторон.
Возвращение снизу показывает последнее состояние,
а не сбрасывает блок на первое.

Нативную прокрутку не перехватывать.
Без wheel-hijacking и глобального scroll-snap.

Сохранить каскад:
маркер → заголовок → описание → изображение.

Для смены сцены использовать существующий исправный движок,
адаптировав его под каждый layout:
— старый текст выходит через маску;
— новый заголовок появляется раньше описания;
— изображение появляется следом;
— после перехода есть неподвижный участок чтения.

Без двоения текста, прозрачного смешения фотографий,
пустых промежуточных кадров и autoplay после остановки скролла.

Начальный ориентир — существующий трек около 473svh
с панелью 100svh для четырёх состояний.
Рассчитать геометрию отдельно для каждого варианта.
Не делать содержимое панели высотой 473svh.

Клик по пункту ведёт к соответствующему участку чтения.
Навигация доступна с клавиатуры.
Скрытые элементы не остаются в tab-порядке.

У каждого варианта:
— уникальные ID секции, сцен, заголовков и диалогов;

Не использовать глобальный querySelector, который всегда

Добавление вариантов не должно заранее проигрывать треугольник
или ломать закрепление блока каналов.
