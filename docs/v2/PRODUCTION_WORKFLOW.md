# Twin V2 — единый вход в производство
Команда: «Сайт Twin — производство. [Что меняем]. Референс: [выбранный файл]. [Подготовить / реализовать / проверить]».
Координатор — .agents/skills/twin-site/SKILL.md; единый процесс — references/production-workflow.md этого навыка. Он связывает концепт → инженерный разбор → заказы на графику → код → отдельную приёмку → выпуск.
Обновление системы не запускает переделку сайта и генерацию автоматически. В рабочей задаче агент сам заполняет артефакты, выбирает ответственных и продолжает после исправления блокеров. scripts/production_next.py только определяет следующее обязательство; он не запускает API моделей.
Формат статуса — .agents/skills/twin-site/references/run-template.json. Для новой задачи скопировать его в папку задачи; заполнить TASK/content/visual-contract/asset-jobs и evidence реальными путями. Запуск проверки:
python3 .agents/skills/twin-site/scripts/production_next.py <task>/run.json .
Обычная обработка и улучшение качества выбираются по references/image-routing.md. Примеры графических слоёв Twin — ASSET_PRODUCTION_PLAN.md. Для переноса макета frontend читает свои reference-to-code/asset-production/parallax/visual-review.

## Следующий настоящий запуск
Подготовить конкретную задачу для связки hero/Journey по последнему выбранному локальному референсу. Фронтендер проверяет исходники, заказывает только недостающие слои. Никакие graphics-ready или visual-accepted в этом обновлении не установлены. Полная V2 не считается одобренной владельцем.

## Граница автоматизации
Агент может вести последовательность и выполнять доступные действия. Навыки не создают независимых сотрудников сами по себе. При отсутствии imagegen в Codex заказ выполняется координатором здесь с последующей передачей реального файла. Для фонового межсервисного диспетчера нужны отдельный runner, API-доступы и бюджет — сейчас он не установлен. Отдельный reviewer доступен только при фактическом запуске отдельного агента/процесса; при лимите статус остаётся pending, не PASS.
