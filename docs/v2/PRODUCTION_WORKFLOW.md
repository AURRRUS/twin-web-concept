# Twin V2 — производство

Вход: `AGENTS.md` → `.twin/START.md` → `.twin/state.json` → соответствующая задача и её HANDOFF. Текущие ветки, candidate и опубликованная версия хранятся в реестре, не в этой инструкции.

Координатор — `.agents/skills/web-production/SKILL.md`; общий процесс и интерфейс — его `references/factory-contract.md`, `workflow.md`, `codex-handoff.md`. Frontend Engineer отвечает за инженерную реализацию, Twin Site — адаптер проекта. Другого общего координатора нет.
Для новой задачи использовать `.agents/skills/web-production/references/run-template.json` (schemaVersion=2). Команда следующего обязательства:

```sh
python3 .agents/skills/web-production/scripts/production_next.py <task>/run.json .
```

Старый путь Twin Site оставлен как compatibility wrapper. Скрипт определяет обязательство, не запускает агентов и не оценивает красоту. Миграция старого run сохраняет неизвестные/непроверенные состояния открытыми.

FE разбирает reference на типографику, геометрию, источники и слои; сверяет объект, общий canvas, crop/anchor/alpha, desktop/mobile. Затем формирует заказы, принимает пригодность материалов и собирает статику → адаптив → motion. Сперва контрольный образец, потом серия. Инструкции слоёв Twin: `ASSET_PRODUCTION_PLAN.md`; исторический план не означает наличие готовых файлов.

Реальный исполнитель и независимый reviewer записывают ID, scope, входную версию и evidence. При отсутствии генератора/браузера/подагентов конкретное обязательство передаётся в доступную среду без выдуманного выполнения. Автоматического фонового межсервисного dispatcher здесь нет.

Технические проверки, визуальный verdict, одобрение владельца и deployment фиксируются отдельно. Разрешение candidate читать по `publicationAuthority.source`; scope текущей workflow-задачи не расширять. Открытый архитектурный mask-дефект должен оставаться видимым до реального исправления и приёмки. Текущий следующий шаг берётся из HANDOFF, а не из старого текста «запустить производство».
