# Twin V2 — производственный план
## Цель и границы
Создать отдельную редактируемую версию сайта Twin на существующем Astro + React, сохранив V1 и работающие demo/compare-ссылки. Этап 1 VIS-002: первые два экрана и их общий переход. Не считать этот этап готовой новой главной всей длины.

## Два этапа
1. VIS-002: отдельный entry, hero, переход в Journey, 4 режима, desktop/mobile, scroll/click, отдельный выпуск. Точная спецификация в .twin/tasks/VIS-002.
2. Последующие задачи: Twin в работе → состав системы → каналы → три качества → запуск → контакт. Их создавать после браузерной оценки этапа 1, не навешивать сразу весь новый сайт на непроверенную композицию.

## История страницы
Hero объясняет цифровую инфраструктуру продаж девелоперу. Journey показывает действия покупателя. Twin в работе позволяет попробовать. С «Единой цифровой основы» герой — девелопер, использующий общую модель и связанные компоненты. Четыре канала показывают применение. Три качества объясняют предложение, затем процесс и запрос демонстрации.

## Перевод референса в код
Общий приём: одно пространство проекта меняет роль — фотография → интерфейс исследования → интерактивная проба → центр цифровой системы → применение в каналах. Не рисовать произвольные диагонали между любыми блоками.
Текст, форма, навигация, раскрывающиеся элементы — семантический HTML. Линия и маска перехода — SVG/CSS. Архитектура и product UI — оригинальные файлы. Растр ImageGen — только ориентир отношений и характера, не фон с вшитыми буквами.
Новые виды/скрытые грани здания по образцу AI-картинки не выдумывать. При недостатке фотографии использовать исходный кадр с простым архитектурным сечением; не заменять принятую сцену универсальным шаблоном молча. Отступление описать в RESULT.

## Карта остальных разделов (следующий этап, не scope VIS-002)
- Twin в работе: «Попробуйте Twin в работе», бронза «Twin в работе». Использовать существующее demo как демонстрацию; не заявлять подключение настоящего API.
- Состав: «Единая цифровая основа», бронза «цифровая основа». Центр public/media/composition-core-20261023.png (сверить глазами: весь проект), допустим public/media/core.webp после проверки. Подпись «Коммерческий цифровой двойник». Шесть групп: клиентские инструменты, виртуальный отдел продаж, контент, управление и аналитика, интеграции, коммерческие модули. Не квартира в центре.
- Каналы: «Четыре канала — одна основа», бронза «одна основа». Четыре состояния: на сайте, дистанционно, через агентов, в офисе. Обратимая стопка; не дублировать Journey. Использовать актуальные реальные изображения, офисный AI-референс не обещает готовый ассет.
- Качества: «Обычно предлагают выбрать два» → «В Twin сходятся все три качества», бронза «все три качества». Три независимых текстовых якоря, модель не перекрывает надписи. «Эффектно» → «Эффективно». В текущем сайте указаны 3 месяца/5 млн ₽: это существующие заявления, в VIS-002 их не менять и не утверждать заново; перед переносом на V2 проверить коммерческий статус.
- Запуск: четыре открытые группы с видимыми названиями и описаниями, не мелкая линия микротекста.
- Контакт: отдельная композиция с графитом допустима здесь (запрет чёрного относится к Journey); без белого прямоугольного блока на пустом поле. Демонстрационная форма, backend не подключать фиктивно.

## Совместная работа
В V2_START закреплён вход для ChatGPT/Codex. В каждой задаче: baseline → scope → точные данные → инженерные значения → состояние → проверки → publication. RESULT содержит исходный commit, проверенные размеры и ограничения; HANDOFF — актуальный branch/head, что сделано, следующий шаг. Одновременно не пушить изменения в одну ветку без fetch/diff. Для независимых задач — work/twin-v2/<ID>, затем обычный merge/PR без force. V1 canonicalBranch не менять на V2 до явного решения о переключении.
