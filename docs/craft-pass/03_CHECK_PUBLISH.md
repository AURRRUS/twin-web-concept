# Проверка и немедленная публикация

Ниже — внутренние проверки исполнителя. Скриншоты и видео не являются deliverable и не требуют одобрения владельца.

1. Шрифты фактически загружены. H1 Expanded400; H2 Expanded400; навигация Expanded40018/26; body Inter Tight400. Не принимать computed имя при фактическом fallback. Верифицировать реальный custom font и нужную кириллицу.
2. Навигация: title/description block в grid wrapper; описание ниже заголовка. Нет пересечения с картинкой при1280×800,1366×768,1440×900,1920×1080. На390/320px нативная последовательность без горизонтального overflow. Нет обрезки из-за фиксированной высоты.
3. Hero100svh на desktop, следующий экран не торчит снизу при top=0. На телефоне естественная высота. Засветки нет. В шапке контурная «Обсудить проект» ведёт к форме, в hero заполненная «Посмотреть Twin» ведёт в/demo. Фраза «через агентов…» начинается отдельной строкой. Заголовки без конечных точек.
4. Journey: медленный и быстрый прямой/обратный scroll, wheel и trackpad если доступны; остановки в текстовом входе и раскрытии медиа; клики по трём пунктам. Нет очереди незавершённых анимаций, двоения UI, скачков рамки, перепутанного active. После перехода background→foreground и resize состояние соответствует позиции страницы. Увеличение host длины не должно создавать пустое место вне sticky-сцены.
5. Reveal: пройти product→composition→channels→delivery→contact. В каждом разделе присутствует последовательное проявление, возврат не запускает его заново. Проверить прямую навигацию к якорям, focus, отсутствие JS и reduced-motion. Все controls доступны сразу при взаимодействии. Не прятать уже видимый контент при гидрации.
6. Performance: снять короткий browser Performance trace в рабочем окружении во время перехода, посмотреть long tasks и frame time. Цель≈16.7ms при60Hz — бюджет, не обещанный результат. Не писать «идеальные60fps» по одному прогону. При тяжёлом frame сначала убрать лишние observers/React renders/постоянные will-change, не снижать разрешение всех исходников без причины.
7. Typecheck, build:preview и существующие релевантные тесты. Обновить прежние ожидания H1 weight600 на400, nav600 на400, host270svh на340svh и clip-top наclip-right. Не отключать тесты целиком. Приложенные численные проверки подтверждают только чистую функцию, browser integration обязан проверить исполнитель.
8. Зафиксировать исходники, отправить рабочую ветку, build:preview и publish:preview. Дождаться build-version.json с новым sourceCommit, проверить HTTP200 главной/demo/font assets и живое поведение. Не завершать работой только в локальном preview. Новое разрешение на публикацию не требуется.

Итог владельцу: опубликованная ссылка с новым SHA, выполненные правки и только реальные оставшиеся ограничения. Не выдавать интеграционные модули из этого архива за уже опубликованное исправление. Не обещать «шедевр» без просмотра результата.
