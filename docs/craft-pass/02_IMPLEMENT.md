## Навигация Journey — полная структура

Применить grid из craft.css. Реальная DOM-структура уже подходит: button→number + span→strong + description. У всех уровней явные display. Это не задача «добавить пробел» между склеившимися надписями. В computedStyle title и description оба block, wrapper grid. Описание начинается ниже названия минимум на8px. При1366/1440/1920 слово «Пространство» и описание находятся внутри224px навигационной колонки, правый край не достигает рамки изображения. Сохранить номера, active и клавиатурное управление. Не применять ellipsis.

Не анимировать hover-подъём пунктов. Выбранность: цвет названия, короткая бронзовая черта, номер. Переход цвета200ms. Тонкую связь с фасадом сохранить как декоративную, не выдавать за точное местоположение лота.

## Управляемый каскад Journey

Вместо старой функции поставить implementation/journeyFrame.mjs, адаптировав её в TypeScript. Сохранены возвращаемые поля text/textY/clip/stack/active/title/explanation, поэтому существующее применение CSS-переменных подходит. ВАЖНО: clip теперь задаёт ПРАВЫЙ inset. Обновить CSS и функцию вместе, иначе получится чужая механика.

Desktop host340svh, sticky100svh. P0–.14 — проект; .14–.44 — переход к пространству; .44–.56 — пространство; .56–.86 — переход к лоту; .86–1 — лот. При936px пути2246px, переход≈674px вместо318px. Это начальная настройка нового исполнения, а не доказанное ощущение премиального скролла на всех устройствах.

Внутри каждого перехода q:

| q | Действие |
|---|---|
| 0–.20 | Текстовая группа старой сцены opacity1→0, Y0→−14px |
| .20–.50 | Новая группа opacity0→1, Y18→0px; H2/eyebrow/body согласованы |
| .40–.96 | Новое непрозрачное изображение раскрывается слева направо, inset-right100→0%; старое лежит под ним |
| .96–1 | Чистое новое состояние |

Текст начинает входить раньше изображения. Nav active меняется на q=.50; ARIA title/explanation соответствует текстовому слою. Рамки и высота текста неподвижны. Без размытия, масштабирования фото, прозрачного смешивания UI или очереди таймеров. При возврате тот же P даёт тот же frame. Точки остановки navigation обновить с прежних значений на sceneTargets=[.07,.50,.93].

Для сглаживания подключить createProgressDriver(read,write) из того же файла ВМЕСТО существующего rAF update/request, а не поверх второго цикла. read вычисляет clamp(-hostRect.top/(hostHeight-panelHeight)); write применяет frame и setReading по изменению дискретных индексов. request вызывать на passive scroll; snap после configure/fonts/resize. Не создавать driver до завершения font load и fit. На hidden отменять кадр/не крутить цикл; при возврате visibilitychange вызвать snap. На отключении enhanced и cleanup вызвать destroy. При повторном configure сначала уничтожить старый driver.

Демпфер80ms относится только к графическому состоянию Journey. Он не подменяет scrollTop и не перехватывает wheel/touch. При большом скачке>0.30 progress сразу актуальный frame. После остановки нет долгого «догоняющего автобуса». Никакого CSS transition на свойствах, уже управляемых rAF. Mobile и reduced-motion — статические три сцены, host height:auto. Низкий desktop: измерять fit по реальным шрифтам и полному тексту, не прятать абзацы.

## Появление всей остальной страницы

Интегрировать reveal.mjs. Удалить прежний механизм .reveal-ready у тех же элементов, старые product-appear/supporting-appear на охваченных узлах: один элемент — один механизм. Не анимировать одновременно родителя и его содержимое.

Назначить data-craft-reveal листовым смысловым группам; data-craft-delay:

| Область | Очерёдность |
|---|---|
| Product | eyebrow0, H2 60, пояснение120, весь workspace180; элементы внутри workspace дополнительно не двигать |
| Composition | header0; центральная модель120; боковые узлы попарно сверху вниз180/200/220, связи проявляются вместе с соответствующей парой |
| Channels | текстовый header0 и изображение160; tab-controls внутри header остаются вместе, переключение таба не перезапускает entrance |
| Delivery | вводный текст0, визуальный центр120, параметры180; четыре шага последовательными группами0/60/120/180 при достижении их собственной зоны |
| Contact | текст0, форма120; focus не задерживается и не блокируется |

Вход один раз: duration800ms, cubic-bezier(.16,1,.3,1), Y20→0px, opacity0→1. Trigger — вход в88% viewport; задержка≤220ms. Не заставлять движущуюся страницу ждать красивой анимации. Изначально видимые элементы не скрываются; без JS всё читается; reduced-motion сразу финал; фокус открывает отложенный блок. Модуль возвращает cleanup, подключить его к существующему lifecycle Astro/React; при повторной навигации не плодить observers. При смене route завершать animation и освобождать listeners.

Hero готов с первого кадра, первичный контент не скрывается до проигрывания заставки. После Journey новые секции появляются последовательно; не создавать вторую pinned-сцену на каждом блоке и не делать одинаковый подъём целой полосы.
