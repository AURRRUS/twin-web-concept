# Приёмка демо Twin и мобильных сценариев

## Q00. Правило результата
Статусы: NOT_RUN / PASS / FAIL / BLOCKED. Для PASS нужны среда, версия сборки, шаги и наблюдаемый результат. Проверка документа не доказывает работу кода. Контрольные ширины: 320/360/390/430/768/1024/1440 CSS px; браузерный эмулятор не заменяет физические устройства.

## Q02. Mobile-матрица
Проверить Safari iOS и Chrome Android на реальных доступных устройствах; точные версии записать при испытании. Проверить портрет, смену ориентации, safe-area, динамические панели браузера, клавиатуру в форме, открытие/закрытие карточки, длинные названия, масштаб текста, reduced-motion, touch targets и конкуренцию жестов с прокруткой. Нельзя требовать landscape для контакта/каталога. При низкой производительности доступен резерв без потери выбранного лота.

## Q03. Этапные гейты
A: оболочка, fixture, адаптивность, недоступность, ссылка и форма без ложного успеха. B: реальный handshake, выбор/ID, отказы, устройства и измерения. C: настоящая доставка, повтор и журнал. Отсутствие viewer блокирует B, не A. Перед публичным демо проверяются права на проект и материалы. Уменьшенный набор испытаний не объявлять полной приёмкой master.

## Q04. Текущее состояние
Все DEMO-Q01…15: NOT_RUN — код/подключённый viewer этим архивом не создавались. Структура документов и целостность архива проверяются отдельно в PACKAGE_VALIDATION.json.
