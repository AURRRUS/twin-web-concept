# Twin by TALENT — Cinematic Web Motion Layer

Стартовый порядок и распределение ролей источников: `../START_HERE_TWIN.md`. Визуальная композиция — по концептам; UI-каталог задаёт содержание и поведение состояний.

Версия 1.1 · 18.10.2026 · METHOD / IMPLEMENTATION ADD-ON. Исполнимая спецификация для сайта; код, видео и проверенная анимация в этот пакет не входят.

## 1. Ведущая мысль

Движение раскрывает одну цифровую модель в разных масштабах и применениях: проект → пространство → выбранный лот → компоненты продукта → каналы → реализация. Объект выбора сохраняется, окружение меняет роль. Не наследовать Bronze System Path ПИН: в Twin бронзовая линия нужна только для конкретной связи выбранной части с объяснением или компонентом. Сквозной неоновый путь по всей странице не нужен.

Сначала статичная истина, потом motion. Любая сцена должна быть понятной при остановке, без JS и при reduced motion. Пользователь может сразу прочитать H1 и нажать CTA. Весь смысловой текст, формы и управление — DOM; SVG/Canvas не заменяют интерфейс.

## 2. Технический подход

Сохранить stack repo. Старт — CSS transition + IntersectionObserver и один планировщик scroll progress. Для сложного pinned chapter допустим GSAP/ScrollTrigger, только если это оправдано согласованной сценой; не добавлять одновременно несколько управляющих скроллом библиотек. Нативный scroll по умолчанию; Lenis не обязательный baseline. Изометрическая модель первого прохода — прозрачный PNG + DOM hotspots и SVG-линии. Это не live3D, не rotation orbit и не повод подключать Three.js.

Токены движения (предложение): `fast=160ms`, `ui=240ms`, `scene=420ms`, `ease=cubic-bezier(.22,1,.36,1)`, выход opacity — `ease-in`180ms. Hover translate≤2px, revealY≤16px, image scale≤1.02 при пригодном исходнике. Не анимировать размеры карточек, reflow текста и цифры стоимости/срока. Назначенные duration — стартовые параметры, подлежат visual QA.

## 3. Контракт одной сцены

`SceneConfig { id, enabled, trigger, start, end, stateIds, reducedState, mediaIds }`. `SceneState { progress, activeState, ready, reducedMotion, suspended }`.

При resize пересчитать геометрию после layout/fonts, не менять выбранный lot/component/channel. В hidden tab и вне viewport остановить ненужные rAF, но не сбрасывать выбор. При ошибке медиа показать poster/DOM, сохранить контролы. При слабом устройстве отключить pin/parallax до упрощения содержания. Один источник состояния на сцену; DOM, SVG и media читают его, не запускают независимые таймеры.

## 4. Режиссёрская карта

### M01 — Вход

Цель: B2B-категория, масштаб проекта и доступное демо.

Trigger: initial render. H1, меню, обе кнопки и poster видны немедленно; без заставки. Только supporting micro-elements разрешено проявить за0–240ms, opacity0→1,Y8→0. Poster не задерживать ради intro. На первом25% прокрутки hero допустим crop scale1.00→1.015 с неизменным `transform-origin:75% 50%`, если края кадра выдерживают. Текст стоит неподвижно. Обратная прокрутка возвращает crop; intro не перезапускается. Mobile/reduced — без crop drift.

Ресурсы: `01_HERO_COASTAL_PROJECT_BG.png`. Это один плоский кадр. Не разбирать его на фиктивный foreground/background и не обещать настоящую глубину без отдельных согласованных слоёв.

### M02 — Сквозная архитектурная история

Цель: связать преимущество проекта с пространством и конкретным лотом.

Desktop: обычная последовательность сохраняется в DOM. При ширине≥1280 и высоте≥800 можно включить один sticky media chapter. Предлагаемый контейнер260svh, sticky-stage100svh, реальный scroll travel160svh. Progress `p=clamp((scrollY-start)/travel,0,1)`.

| Диапазон p | Состояние | Видимое изменение |
|---|---|---|
| 0–0.28 | project | Фасад-опора слева, контекст справа, выноска «Окружение и архитектура» |
| 0.28–0.36 | переход | Панорама→интерьер crossfade, общая опора и текстовая ось сохраняются |
| 0.36–0.64 | space | Терраса/интерьер справа, «Территория и пространство» |
| 0.64–0.72 | переход | Появляется выделение лота, интерьер уступает место плану |
| 0.72–1 | lot | План и «Планировка, положение и вид»; подготовка к UI |

Crossfade по linear progress внутри переходного окна, не дополнительный «догоняющий» autoplay. Общий фасад сдвигается только в пределах5% высоты изображения. Выноска связана с видимым предметом, текст не движется во время чтения. При reverse — все transitions обратимы. Не вращать и не «взрывать» этажи.

Если кадры не совпадают геометрически, использовать мягкий монтаж между согласованными кропами; запрещён morph с ложной трансформацией зданий. Один портретный фон не обеспечивает непрерывную3D-камеру. Нужны реальные camera-matched слои/sequence для advanced pass.

Mobile, короткий viewport и reduced:3 последовательных открытых материала, без pin и без opacity0. Anchor navigation прокручивает соответствующий материал. Активный маркер определяется положением DOM, не анимационным таймером.

### M03 — Передача в интерфейс

Цель: выбранный лот становится объектом работы продукта.

Trigger: UI входит35% в viewport. Базовый pass — план и UI уже в правильных конечных местах; одно появление400ms (opacity,Y12). Если согласованный один и тот же PNG плана используется в двух сценах и между ними нет ломкого layout, возможен shared-element transition; иначе обычный crossfade. Не заставлять plan лететь через весь экран.

Вкладка Планировка/Вид: click/keyboard, текущий контент→новый за200ms opacity, размер viewport фиксирован. Быстрые повторные клики прерывают старый transition и приводят к последнему выбранному состоянию. Без дублирования ID/focusable controls в crossfade layers. Media loading не сбрасывает lot. На reduced — мгновенная смена; положение и подпись сохраняются.

### M04 — Изометрическая карта состава

Цель: показать ядро и шесть связанных компонентов на уровне состава продукта.

Initial: ядро и ВСЕ6 названий видимы, доступные кнопки сразу работают. При first enter разрешено160ms проявить тонкие SVG-связи параллельно, без длинного поочерёдного ожидания; не заставлять карту собираться как заставку. Никакой бесконечной levitation модели.

| Состояние | Trigger | Движение / содержание |
|---|---|---|
| overview | enter / close | Все6 равноправны, коммерческие модули помечены расширением |
| focused(id) | hover / keyboard focus | Контур связи и заголовок активны, Y0→−2px160ms; соседние не исчезают |
| opening(id) | click / Enter | Диалог opacity0→1, scale.985→1 за240ms; фон overlay0→.38 за180ms |
| dialog(id) | завершение | Читаемый состав, медиа и CTA; неподвижный background |
| closing | Escape / × / back |180ms opacity; возврат URL и фокуса на исходный компонент |

Фокус переводится внутрь диалога сразу после открытия в логическом DOM; анимация не удерживает старый focus. Режим reduced: без scale, fade≤80ms или мгновенно. Focused не обязательный этап перед click. В touch не открывать «hover-экран» первым нажатием. На mobile карта → макет + список6 кнопок; диалог на весь экран с собственной прокруткой и устойчивой кнопкой закрытия. При длинном диалоге у заголовка `tabindex=-1`, перенос фокуса без скачка body.

Изометрические ветки и управленческие интерфейсы в составе не должны анимировать выдуманные live-данные. В будущем route resolver может открыть страницу вместо диалога; анимация не должна быть связана с pathname жестко.

### M05 — Каналы продаж

Цель: один проект доступен в четырёх коммерческих сценариях.

Trigger только click/keyboard, без carousel autoplay. State `site/online/agent/office`; текст и медиа обновляются вместе за240ms. Media viewport сохраняет aspect-ratio, минимальную высоту текстовой части вычислить из максимального контента, чтобы избежать скачков. Selected tab underline переводится transform за160ms; active state обозначен не только цветом. Стрелки переключают tabs, Home/End поддержаны. На touch — читаемые4 tabs с видимой горизонтальной прокруткой при необходимости, page body не выходит за viewport. Без video/audio autoplay. Ошибка/отсутствие media: иллюстративный poster + соответствующий текст, не подмена другим каналом.

### M06 — Треугольник реализации

Цель: три опоры вместе; не рейтинг рынка и не вычислительная диаграмма.

На enter30% блока можно анимировать только SVG-рёбра. Все цифры, пояснения и CTA видны с первого кадра. Абсолютный локальный timeline после trigger:

| Время | Объект | Операция |
|---|---|---|
| 0–0.24s | Первая связь | strokeDashoffset1→0, ease-out |
| 0.12–0.36s | Вторая связь | то же |
| 0.24–0.48s | Третья связь | то же; все вершины уже читаемы |
| ≥0.48s | Завершённый треугольник | статический hold, без пульсации и счётчиков |

Текст «Обычно предлагают выбрать два» — подводка, не выбор, который пользователь обязан пройти. Не отключать качество при выборе срока/стоимости. «3 месяца» и «В среднем5млн ₽» не исчезают и не становятся промежуточными числами. Качество раскрывается переходом к настоящему демо, не числовым индексом. На mobile —3 опоры списком с миниатюрным треугольником как декором. Reduced: полный SVG сразу. Обратный scroll не перезапускает нарисованные линии.

### M07 — Этапы и обращение

Последовательность4 этапов без scrub/пина, однократный fade≤240ms допустим, весь текст остаётся доступным. Форма статична; focus/validation feedback быстрые и локальные. Submit не вызывает уход всей страницы, смена кнопки сохраняет её ширину; loading indicator имеет текст. На error сохранить введённое, указать действие. На success только при реальном успешном ответе сервера. В prototype честная демо-индикация.

## 5. Media sequence / video readiness

Если понадобится реальный облёт: отдельное задание на согласованную3D/video-сцену, камера/геометрия фиксируются по реальным исходникам. Статичные изображения в пакете не являются кадрами одной последовательности. Нельзя интерполировать их и объявлять документальным пролётом.

Для короткого подготовленного sequence: `window.ready` для ресурсов; deterministic `render(t)` при offline экспорте; live-driver отдельно. В web first-pass предпочитать poster/video илиDOM, не сотниPNG. Не поднимать96–160frames из старого PIN-документа как обязательный бюджет. Canvas draw черезrAF, resize observer, DPRcap1.5 как старт, lazy preload близко к сцене, bounded cache, отмена загрузок при уходе. Визуальный результат и фактическую память измерять. При нехватке памяти — poster, а не сломанный canvas.

## 6. Performance и QA

Цель60Hz — бюджет~16.7ms/frame, не гарантия. Измерить frame cost на согласованных desktop/mobile, Safari/iOS отдельно. Предпочитать transform/opacity, избегать blur больших поверхностей, нескольких sticky pin одновременно и layout reads/writes в одном loop. На hidden tab и вне сцены pause. Отменять listeners/context при unmount. Не добавлять второй smooth-scroll driver.

Приёмка каждой сцены: enter/mid/exit + reverse; очень быстрая прокрутка; resize; navigation by anchors; tab/focus; Escape/back; загрузка/ошибка медиа; медленная сеть; reduced-motion; touch; portrait/landscape. Проверить сцены при320/390/768/1024/1440/1920px. Обязательно остановиться на любом переходе: контент должен оставаться понятным. Смена пользовательской настройки reduced motion применяется без перезагрузки. CLS по reserved sizes; LCP hero не ждёт motion bundle.

Порядок: static pass→M02→M04→M03/M05→M06→measurement. После каждой сцены снять реальные screenshots, исправить фактические дефекты. Отчёт: какие эффекты реализованы; что отключено на mobile; какие fallback; measured performance и устройства; недостающие3D/видео/медиа. Этот документ задаёт план; проверок работающего сайта пока нет.
