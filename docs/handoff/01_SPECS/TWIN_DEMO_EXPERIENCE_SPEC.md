# Демонстрация Twin: сценарии и состояния

## D00. Целевой путь
Понять продукт → открыть демо → выбрать доступный уровень проекта → рассмотреть лот и материалы → запросить показ для своего проекта. Ведущий менеджер может использовать тот же адрес и вручную вести показ; совместная сессия не считается реализованной.

## D01. Два честных режима
`fixture` — локальный демонстрационный интерфейс на данных пакета; подпись «Демонстрационный интерфейс». `connected` — фактически подключённый Twin с подтверждённой совместимостью. Переключение определяется конфигурацией и проверкой готовности. Изображения из AI-концептов не являются настоящим двойником.

## D02. Структура /demo
Заголовок/выход на сайт; контекст проекта; область viewer; доступные фильтры корпуса/этажа; представления «Twin / Список / Шахматка» по наличию данных; карточка выбранного лота с планировкой/видом; действие «Обсудить проект». Не требовать контактные данные до первого просмотра.

## D03. Единый выбор
**DX-01.** Один selection store: projectId/buildingId/floorId/lotId/view. Все представления читают его; viewer сообщает намерение выбора через адаптер.
**DX-02.** Смена родителя сбрасывает несовместимые дочерние значения. Невалидная ссылка сохраняет доступный уровень и объясняет отсутствие лота.
**DX-03.** Viewer без API выбора не получает фиктивные двусторонние controls: явно указать, какие связи доступны. Список остаётся работоспособным.
**DX-04.** Начальный fixture использует только доступные записи v1.1: один корпус, этаж, лот и два медиасостояния. Для полноценной шахматки нужны новые согласованные записи. Один лот не выдавать за полный ассортимент.

## D04. Состояния и восстановление
idle → loading → ready. loading также может завершиться timeout/error/unsupported. Порог ожидания настраивается после измерений, не выдумывается как SLA. Есть отмена запуска, повтор и переход к списку. Ошибка viewer не ломает навигацию, каталог и форму. Пауза скрытой вкладки и уход со страницы освобождают ресурсы; повторное открытие восстанавливает валидный выбор.

## D05. Mobile
Портретный режим обязателен для выбора и обращения. Viewer получает отдельный экран, компактные controls и нижнюю карточку; одновременно открыт один перекрывающий слой. Полноэкранность браузера — улучшение, а не обязательное условие. Жест внутри сцены не захватывает прокрутку всей страницы до явного входа в просмотр. Выход из просмотра и системный Back предсказуемы. Без подходящего рендера/сети — планировки, виды и список с тем же выбором.

## D06. Материалы перед подключением
Получить разрешённый URL/build viewer, поддерживаемые устройства, список доступных сцен/объектов, карту ID, способ авторизации, разрешённые origin, интерфейс команд/событий, права на публикацию, известные ограничения, контакт технического ответственного. Это зависимости этапа B; независимая оболочка A продолжается.
