# Как реализовать скролл и появление

## 1. Три независимых уровня

Layout: только размеры/сетка, никаких анимаций. Entry: короткое появление внешней .entry-shell. Scene: смена внутренних .story-copy и .story-photo по локальному progress. Нельзя применять две анимации transform/opacity к одному DOM-элементу. На scroll-driven слоях не использовать CSS transition:all/animation — значения туда пишет только paint.

Pure frame-функции приложены в reference. Они показывают математику, совместимую по полям с current useStoryTrack. Их можно перенести в src/lib/salesStoryFrame.mjs с новым motion.json; после переноса адаптировать измеритель и проверить интеграцию. Не объявлять весь сайт протестированным по тесту этих функций.

## 2. Геометрия дорожки

У каждого экземпляра отдельные root/ref/observer. Sticky top0; header сайта не фиксируется поверх этих сцен. Если фактически фиксирован — вычесть реальную его высоту в panel и geometry, не дублировать 100vh+header.

T=host.getBoundingClientRect().top+scrollY; H=host.offsetHeight; V=panel.offsetHeight; L=max(1,H-V). p=clamp((scrollY-T)/L,0,1). Источник положения — host, который не получает transform. Не использовать общую высоту страницы или progress предыдущей секции.

Journey host460svh/panel100svh, полезный 360svh. Channels host400svh/panel100svh, полезный 300svh. Считать именно DOM-высоты, а не предполагать innerHeight===100svh. Измерять после fonts.ready и стабильной раскладки, при resize/breakpoint и при изменении геометрии предшествующего контента. По обычному scroll не запускать configure.

Перед сменой mode сохранить active/p. Если окно сменило размеры, восстановить ту же сцену; при необходимости сделать одну контролируемую коррекцию позиции только для находящегося на экране pin. Не прокручивать страницу при каждом img.load. После выхода из секции scroll остаётся обычным.

Записывать transforms только в одном rAF на событие. Сначала прочитать scroll/geometry один раз, затем все записи стилей. Без перемежения offsetHeight→style→getBoundingClientRect для каждого слоя. Если применённый p не изменился и assets/mode не инвалидированы — не писать те же стили снова. Не создавать постоянный RAF для всех секций.

## 3. Journey — чтение и короткая смена

Чтение: [0,.19], [.27,.46], [.54,.73], [.81,1]. Переходы: [.19,.27], [.46,.54], [.73,.81]. Навигация ведёт к серединам чтения .095/.365/.635/.905 через T+target*L.

Локальный t внутри перехода 0…1:
- заголовок: старый 0–.12 уходит через собственную маску,Y0→-10px; новый.14–.36,Y12→0px;
- вопрос: старый.05–.20; новый.30–.58;
- изображение: старый opacity1→0 на.30–.48; новый 0→1 на.50–.68; новый scale1.025→1,Y12→0 на.50–.90;
- вывод для продаж: старый.12–.28; новый.74–1;
- новый active для nav на t=.55.

Это не последовательные автотаймеры: каждое состояние — функция p. При остановке скролла внутреннее движение останавливается; обратный скролл воспроизводит обратный путь. Только generic entry может коротко завершиться по времени. Никакого once для смены 4 сцен.

Изображения не смешиваются полупрозрачными двумя интерфейсами. Не возвращать старую маску, где план закрывал половину корпуса. В коротком промежутке.48–.50 допустима нейтральная подложка; при нормальном ходе это узкая зона. За ней не должен быть дырявый DOM/скачок высоты. Продолжительное пустое изображение — ошибка интеграции. При static/reduced-motion переключить непосредственно, без этого перехода.

У text-slot grid все четыре текста участвуют в расчёте максимальной высоты, но доступны и видимы только нужные. Не делать display:none так, чтобы высота менялась на каждом состоянии. Не двигать header/nav при смене длины вопроса.

## 4. Channels — обратимая стопка

Полезная дорожка 300svh: чтение 0–45, переход 45–85; чтение 85–130, переход 130–170; чтение 170–215, переход 215–255; чтение 255–300. Навигация:22.5/107.5/192.5/277.5svh полезного хода. Матрица в motion.json — источник этой разметки; убрать hardcoded ranges из frame-функции.

Внутри перехода: старый текст 0–.16; новыйH3.18–.42; новое пояснение.34–.62; фото.22–1. Приходящий лист Y=mediaHeight+24→0,scale1,opacity1. Уходящий Y0→-10px,scale1→.975. Чёткий clip контейнера, постоянный z-order по сценам. После перекрытия скрыть старый слой. Текст/меню не двигаются вместе со стопкой.

Индекс active=.60 по переходу. При медленной смене направления допустим hysteresis±.02 для навигационной подсветки, но не задерживать им само фото. Клик по любому каналу ведёт к середине его чтения; reverse восстанавливает предыдущий лист. Никаких autoplay, wheel-lock, обязательного scroll-snap всей страницы, bounce и blur.

## 5. Готовность медиа и повторный вход

Заранее задать width/height/aspect-ratio всех assets. На подходе к host (примерно 1viewport до него) начать loading=eager и decode четырёх картинок. Это preload близкого компонента, не всех сравнений с первой загрузки.

Не менять реальный p ради readiness. Если целевой кадр ещё не готов, выбранная сцена и текст соответствуют фактическому progress; в медиа спокойный placeholder или последний доступный кадр с ясным состоянием загрузки. Не показывать старый кадр как новый без объяснения. При error — локальная заглушка и доступный повтор/развернуть исходник. Decode/error инвалидирует paint даже при неизменном p. img.complete проверить вместе с naturalWidth>0; complete у ошибочного файла не означает успех.

Пересчёт layout на img.load не нужен при неизменных intrinsic размерах. Если действительно поменялся aspect-ratio — отдельная layout invalidation, затем recalc. Cleanup всех слушателей/observer/RAF, в том числе при смене ?compare. Повторный вход сразу рисует кадр фактического p, а не проигрывает сначала первую сцену. Переключение вкладки/Back/bfcache вызывает repaint и восстановление геометрии, но не force-settle всего Journey.

## 6. Reveal всей страницы

Нужны появления групп, а не независимая анимация каждой буквы и каждой иконки. Группы: заголовок+подводка, медиа/демо, отдельная карточка состава, этап запуска, контактная форма. Один внешний элемент группы получает data-entry. Внутренние data-story-* и quality-* исключить из generic observer.

Обычная группа: Y14→0,opacity0→1,duration420ms,easing cubic-bezier(.22,.61,.36,1). В пределах одного осмысленного блока заголовокdelay0, пояснение 60ms, медиа 120ms; общий cascade не растягивать дольше 600ms. Media scale1.025→1 допустим только у отдельной оболочки с clip, не одновременно на iframe/dialog и внутреннем canvas. Для launch stagger70ms,max210ms.

Trigger: IntersectionObserver rootMargin0 0 -12% 0,threshold0. Группа, которая уже видима на стартовой загрузке, остаётся читаемой сразу или входит коротким load-reveal; не скрывать её до следующего scroll. Группа ниже экрана может быть armed перед входом. После одного показа unobserve, финальное состояние сохраняется. На фокус/прямой якорь сразу раскрыть затронутую группу. Быстрый scroll не оставляет пройденные элементы opacity0.

Journey/Channels при первом входе: entry применяется к отдельной внешней оболочке всей композиции один раз 400ms,Y12. Внутренние фазы p начинают работать независимо и не ждутentry. При повторном входе внешнийentry не нужен, но 4 сцены повторяемы. Стопку и Journey запрещено превращать в разовыйfade.

NoJS/ошибкаинициализации/reduced-motion: весь текст, первый кадр и controls видимы. Скрытие привязано к успешной регистрации observer, а не только .has-js. При reduced-motion отключить длительные дорожки и использовать direct scene controls; остальные части страницы статически видимы. Если настройку меняют во время сессии — пересобрать observers/режим с сохранением active.

## 7. Качества — один проход

SVG рисуется по pathLength1,stroke-dasharray1 и dashoffset1-progress. Не писать SVG-top/width из общего progress. Факты и модель находятся в фиксированных slots.

Progress монотонный от положения quality-canvas: q=max(previous,clamp((.80*viewportHeight-canvasRect.top)/(.65*viewportHeight),0,1)). До входа не вычислятьq по общей позиции страницы. Схема безsticky. Фазы в JSON: Быстро 0–.20; первая грань.10–.32; Доступно.24–.45; вторая грань.34–.56; Эффектно.43–.61; модель.38–.64; третья грань.52–.73; Эффективно.70–.88; пояснение.77–.97. После полного показа q1 сохраняется.

Модель: Y10→0/scale.98→1, без вращения. Финансовые числа не пересчитывать анимированным счётчиком. Смена слова — две раздельные маски в слоте по ширине большего слова, без смешения букв. И доступный текст соответствует финальному видимому состоянию. Условие эффективности объяснено функциональным текстом, а не выдуманным ROI.

На mobile каждый из 3 аргументов имеет собственный локальныйtrigger; нижние не завершаются до входа. Якорь #delivery не оставляет скрытый заголовок. Позднийresize не запускает всю схему заново. Для увеличенного текста и низкого окна — normal flow.

## 8. Доступность

Скрытые controls inert; если скрывается только декоративное photo — aria-hidden, а контекст доступен через текущий DOM-текст. Клавиатура/тач не должны зависеть от gesture. Не ставить aria-live на каждый scroll-frame. Прямые якоря/возврат из dialog сохраняют сцену, фокус и scroll. Неподвижные табы и CTA доступны без полного прохождения дорожки.
