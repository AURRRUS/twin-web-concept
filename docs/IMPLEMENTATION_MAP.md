# Twin — карта реализации

## Текущий объём

Поручение владельца: реализовать по ТЗ, начать с desktop, использовать этапы сдачи, объяснять простыми словами, не публиковать. Последнее уточнение: v1.3 имеет приоритет над v1.2 при совпадении документов.

TW-00 завершён: базовый комплект доставлен пятью RAR, безопасно распакован, одинаковые дубликаты объединены, OVERLAY v1.3 применён поверх базы. Старый master v1.0 исключён из активного комплекта. Все 76 SHA-256 совпадают с EXPECTED_FILES_v1_3.json. `PATCH_VALIDATION.json` — отчёт упаковщика, не результат тестирования приложения.

## Архитектура

Astro + React + TypeScript, npm с фиксированными версиями и package-lock. Astro выдаёт готовый HTML, React гидратирует интерактивные состояния. Две статические страницы: `/` и `/demo`. Стили — CSS, без дополнительных animation/WebGL библиотек. Node 24; команды в README.

- `HeaderHero.tsx`: S01 / TW-D01.
- `Journey.tsx`: S02 / TW-D02, последовательная фасадная сцена без pin и ложного 3D.
- `Composition.tsx`, `Channels.tsx`: S04–05 / TW-D03.
- `ProductDemo.tsx`, `App.tsx`, `lib/config.ts`: S03, fixture `/demo`, общий проверяемый selection / TW-D04.
- `Delivery.tsx`, `ContactForm.tsx`: S06–07 / TW-D05.
- `Media.tsx`: размеры, lazy/eager, responsive hero, состояние ошибки.
- `site.css`: токены, композиция, базовый reflow и reduced-motion.
- `public/media/`: оптимизированные производные исходных материалов; оригиналы остаются в handoff.

## Контент и подключения

Содержание — актуальные frontend-ТЗ и content JSON. Модалки используют modal-content.json; карта сохраняет core + ровно шесть content IDs. Семантические тексты не извлекаются OCR из картинок. Системная Arial и резервная DejaVu из пакета — временная типографика, не брендовый master.

Публичный конфигурационный контракт `src/lib/config.ts` явно отключает viewer, отправку заявок и аналитику. Это не сервер интеграций. Fixture: example-project / building-1 / floor-4 / lot-4-2; commercial=null. Доступны только эти записи. Родительский выбор сбрасывает дочерний. Адрес переносит только публичные ID и view; контакты не попадают в URL/storage. Форма не отправляет запрос и не сообщает о принятии заявки.

## Карточки desktop

Версия всех карточек: 0.1, входы handoff v1.3 + исходные визуалы v1.2. Общие ограничения: mobile-приёмка отдельно; публикация, CMS/ИИ, настоящий viewer и реальная доставка обращений не входят в выполненный объём. Изменения: source, локальная конфигурация сборки, тесты и документация. Возврат: убрать соответствующее включение компонента из App; оригинальные материалы сохранены независимо.

## Следующие шаги

Desktop можно показывать владельцу по скриншотам и запущенному приложению. Следующий шаг — его замечания по композиции. Затем отдельный mobile-этап TW-M01…03 на общих компонентах и selection, без копии сайта. Админка и ИИ не запускаются автоматически после desktop. Для реальных подключений запросить конкретные материалы тогда, когда выбран этот объём; сейчас ключи не нужны.
