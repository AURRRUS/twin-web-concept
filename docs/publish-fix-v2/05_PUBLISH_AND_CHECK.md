# Проверить и опубликовать в этой же задаче

Владелец дал прямое разрешение на публикацию правки Twin на текущем GitHub Pages. Старые запреты «production не публиковать», «сначала согласовать скриншоты», «сдать только preview» отменены. Не запрашивать повторное разрешение. Не менять домен, видимость репозитория, права доступа или платные сервисы.

## Проверки во время работы

- Дождаться document.fonts.ready; выполнить document.fonts.load для кириллицы на400/600/700 семейства RF Dewi Expanded. Проверить успешные ответы реальных font assets. H1: Expanded600, H2:Expanded400, названия сцен:Expanded600, body:Inter Tight400.
- Проверять точное первое family-name RF Dewi Expanded. Старая проверка /RF Dewi/ ошибочна: она пропускает обычный RF Dewi. При доступном CDP getPlatformFontsForNode подтвердить custom font с именем Expanded; computedStyle сам по себе недостаточен. В пакете есть модуль implementation/assert-twin-type.mjs для подключения к browser QA.
- В 1440×900 H1=48/56 weight600, Journey H2=44/52 weight400. В1366×768 H1=44/52, H2=40/48. В1920×1080 H1=56/66, H2=48/58. Проверить также1280×800,768×1024,390×844 и320px. Без horizontal overflow, обрезки заголовков и изменения размеров зоны при смене сцены.
- Все DOM-заголовки H1–H6 и визуальные названия без конечной точки. Исправить копию в data/TSX/ARIA. Обычные предложения в абзацах сохраняют пунктуацию.
- Узел hero-wash и его определения удалены; вместо него нет нового светлого/размытого overlay. Исходная фотография сохранена, CSS filter:none и opacity:1.
- Прямой1→2→3, обратный3→2→1, быстрый проход и остановка посередине: текстовая группа опережает картинку, рамки стабильны, нет двоения. Проверить навигацию мышью/клавиатурой, reduced-motion, resize. После загрузки нового шрифта enhanced не должен молча исчезнуть на обычном ноутбуке.
- Проверить /demo, действующие секции/якоря и сохранение project/building/floor/lot/view. Форму не отправлять внешним адресатам. Не придумывать работающий backend.
- Выполнить существующие npm run typecheck, npm run build:preview и релевантные тесты. Исправить старые тесты, ожидающие RF Dewi, точки или медиа>780px при любой ширине, на новый контракт. Не отключать проверки лишь ради зелёного статуса. Не добавлять screenshot-approval gate.

## Публикация

В проверенном package.json уже есть build:preview, publish:preview и verify:online. Скрипт publish-preview.mjs публикует dist в twin-preview, сохраняя историю, и пишет build-version.json с sourceCommit. Пользоваться им, не придумывать новый hosting.

1. До коммита адаптировать scripts/verify-online.mjs по пункту3 ниже. Затем зафиксировать исправленные исходники в текущей рабочей ветке и отправить её в origin. Не force-push. Не тащить чужие незавершённые изменения в коммит.
2. На чистом рабочем дереве выполнить npm run build:preview, затем npm run publish:preview. Скрипт требует чистый status и правильный base path /twin-web-concept. Не обходить его проверку и не коммитить dist в исходную ветку.
3. Изменения проверки выполнить ДО коммита и публикации (см.пункт1): обновить scripts/verify-online.mjs под новые точные гарнитуры и геометрию. Удалить обязательное сохранение online-first-screen.png. Удалить предположение, что каждое медиа обязано быть>780px: сверять фактический viewport с геометрией02. Обновить список реально опубликованных topHero/topFacade/sceneProject/sceneSpace/sceneLot, если он ещё проверяет старые имена media. Проверка должна соответствовать новому сайту, а не доказывать старую версию.
4. После публикации задать TWIN_EXPECTED_COMMIT фактическим SHA исходного коммита и выполнить npm run verify:online. Дождаться завершения GitHub Pages и совпадения build-version.json.sourceCommit; один успешный push ещё не доказывает обновление сайта. Проверить HTTP200 для главной, /demo, новых шрифтов и изображений, отсутствие новых ошибок runtime. При ожидании Pages продолжать проверку, не просить владельца разрешить её.
5. Открыть живую страницу с новым параметром v=<короткий source SHA>, убедиться в новом шрифте, отсутствии засветки и конечных точек, работе скролла. Если опубликован старый build — продолжить исправление доставки.

## Итог владельцу

Дать опубликованный URL с фактическим новым SHA и3–5 строк: шрифты/типографика, удалённая засветка, точки, каскад, статус публикации. Не выдавать скриншоты/видео вместо сайта и не завершать вопросом «публиковать?». Если есть реальная блокировка доступа/сети, назвать конкретную ошибку и не объявлять публикацию состоявшейся.
