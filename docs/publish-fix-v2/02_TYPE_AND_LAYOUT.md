Это новая спецификация размеров по решению владельца. Значения рассчитаны с учётом метрик реальных файлов, но должны быть проверены исполнителем в его рабочем браузере. Не выдавать эту подготовку за уже обновлённый сайт.

## Hero: ширина и переносы

Desktop ≥1100px: ровно две смысловые строки, каждая отдельный block span:

«Цифровая инфраструктура продаж»
«девелоперского проекта»

Убрать отдельный принудительный перенос после «Цифровая». Внутри каждой desktop строки nowrap. H1 получает всю ширину общего контейнера; старая hero-copy max-width:1120px отменяется. Максимум полезного контента — 1408px; внешние поля: 64px при ≥1400, 56px при 1280–1399, 48px при 1100–1279, 32px при 600–1099, 20px при <600. Контейнер центрируется, H1/абзац/CTA и видимый край логотипа имеют одну левую опору. Не центрировать текст посередине независимо от шапки.

При 1440px H1 =48/56, weight600; первая строка по сумме advance ≈1100px, внутри 1312px она имеет запас. При 1920px H1=56/66, первая строка ≈1283px внутри 1408px. Это измерение файла без kerning, не заявленная проверка браузера. Новые размеры нельзя заменить прежним clamp(48px,3.9cqw,64px).

Высота header 104px, расстояние header→H1 48px на desktop; H1→абзац 24px; ширина абзаца 520px; абзац→CTA 28px; промежуток между действиями 28px; кнопка 52px высотой, padding-inline24px, radius5px. Hero min-height:clamp(680px,90svh,1000px). Фото cover, object-position:65% center; объект справа сохраняется. Засветление удалить, не уменьшать его opacity.

На ширине <1100px снять nowrap, разрешить естественные переносы без разрыва слов, hyphens:none. Не сохранять две строки ценой уменьшения всего экрана. На телефоне текст идёт отдельной белой зоной, затем исходное фото высотой340px; без градиента на стыке. Убрать прежний искусственный min-height:860px и padding-bottom:432px. Mobile header88px, отступ до H1 24px. При <360px основной CTA и вторичная ссылка могут переходить на следующую строку. Обычный поток определяет высоту, текст не перекрывает фото.

## Journey: три связанные зоны

Desktop ≥1280px: фасад38% ширины сцены слева, постоянный между состояниями; навигация в средней зоне; крупное изображение справа. Общая сцена max-width1920px, margin:auto. Высота sticky100svh. Путь scroll270svh. Не вырезать в фасаде случайные карточки.

Правая зона входит на64px в фасад, имеет справа общее поле контейнера. Нижняя сетка:224px навигация +24px зазор +остаток под медиа. Верхний текст занимает обе правые колонки, отступ слева88px от начала правой зоны (то есть24px от полного края фасада). Правая граница H2/абзаца совпадает с правой границей изображения. Фасад ниже диагонального перехода заканчивается ровно на64px раньше; этим создаётся место навигации без белой наклейки поверх фото. Готовая геометрия в CSS.

Навигация: title20/28 weight600, number12/20, gap8px, number width16px, horizontal padding8px; описания14/20 с отступом8px. Слово «Пространство» в Expanded Semibold20px занимает ≈183.5px — прежняя колонка180px для всей строки непригодна. Новая колонка224px и расчёт внутренних отступов дают184px под название. Не уменьшать это слово отдельно и не обрезать ellipsis.

Текстовая зона: надзаголовок→H2 12px; H2→абзац20px; после всей текстовой зоны24px до медиа. Три текстовых слоя лежат в одной grid-area; высоту определяет самый высокий слой с реальным шрифтом. При смене изображения/текста рамка неподвижна. Две строки H2 по 03_CONTENT.json. На mobile строки могут дополнительно переноситься естественно, текст целиком сохраняется.

Картинка16:9, contain, без изменения пропорций, смешивания/полупрозрачности UI. Полный оригинал открывается существующим доступным действием. Размер правого медиа в этой геометрии при1280px примерно554px, при1440px645px, при1920px750px; не требовать старые >780px на каждом viewport. Встроенный PNG — иллюстрация, не обещание читаемости каждой микроподписи. Основной объект и схема остаются различимы; полный файл доступен.

При ≤850px высоты вертикальные padding правой зоны24px вместо32px, body17/25 только в enhanced desktop. Шрифт H2 и ширина колонок не меняются от высоты. Проверка fit должна ждать фактическую загрузку Expanded; после загрузки и resize пересчитать. При1280×800,1366×768,1440×900 сцена с указанными размерами должна работать с каскадом; не отключать из-за старого порога900px. При реальном недостатке высоты <680px — native flow с тремя сценами, без пустых270svh.

На ширине<1280px — последовательные три сцены с полными текстами и большим медиа, без scroll trap. На телефоне facade320px и навигация вертикально; никаких уменьшенных desktop-колонок.

## Применение CSS

Скопировать implementation/twin-type-and-layout.css в src/styles/; шрифты в src/assets/fonts/. Подключить этот CSS последним из CSS entry. Удалить старые конфликтующие font-family/size/spacing и hero-wash из site.css/top-screens.css; после переноса итоговых правил убрать дублирование. Не вставлять новые !important поверх десятка старых override. Приложенные селекторы относятся к проверенной версии исходников; при переименовании связать их с существующими элементами, сохранив значения.

Семейство RF Dewi обычное больше не должно использоваться для заголовков, навигации сцен и крупных ценовых цифр. Другие H3, для которых существующий UI требует компактного размера (карточка лота, мелкие узлы схемы), используют тот же Expanded600 с существующим компактным кеглем; общая H3-шкала относится к секционным H3. Не ломать демо массовым назначением24px всем элементам.
