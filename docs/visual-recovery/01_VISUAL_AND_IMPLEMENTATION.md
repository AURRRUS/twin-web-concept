# Целевой видимый результат
В эталоне важны: крупная архитектура, связанная пространственная композиция, ясная типографическая иерархия, белые поля как часть рисунка, аккуратные бронзовые акценты и компактные переходы между смысловыми сценами. Не возвращать удалённую владельцем боковую навигацию в hero; не копировать ошибочные переносы H1 из растра.

## Сохраняем содержание
Текущие hero,journey,product,composition,channels,delivery,contact,footer остаются. Продуктовые функции, тексты и CTA ниже первых двух экранов не сокращать. Форма остаётся локальным демо до настоящего подключения. Не добавлять цены/наличие из вшитых изображений в действующие поля. Главная и /demo — разные маршруты; viewer не заменять маркетинговым экраном.

## Hero
Точное содержание —02_CONTENT.json. Desktop: «Цифровая инфраструктура продаж» / «девелоперского проекта.» — две строки при1280px и шире; на узких экранах естественный перенос без сжатия букв. Сохранить новый чистый морской фон «Вид побережье.png». H1 и CTA имеют одну левую опору с основным контейнером. Фон сохраняет крупный архитектурный объект справа и спокойное небо для надписи. Не требовать буквального старого горизонта эталона: используй предоставленный новый кадр.
Текущий hero в проверке: H1 около44.9px при1363px ширины viewport, hero842px при высоте936px. Эти цифры — наблюдение, не желаемые токены. Нужен уверенный масштаб, но не восстанавливать четыре строки ради большого кегля. Подбирать шрифт/размер/ширину совместно по реальному render. Не менять копию для подгонки.
Один контейнер margin-inline:auto, responsive gutter и общий max-width. Левый край контента, видимый край логотипа и CTA связаны; прозрачные поля логотипа компенсировать отдельно. Не центрировать каждый элемент независимо.

## Journey: связная композиция вместо трёх непроницаемых колонок
Сохранить три функциональные зоны, но перестроить их как связанную сцену по эталону. Фасад сейчас занимает около24% экрана и выглядит узкой боковой полосой. В референсе архитектура существенно весомее. Стартовый ориентир фасада:35–40% desktop ширины; это гипотеза компоновки для визуального прохода, не проверенный owner-макет. Проверить вместе с доступной шириной правого визуала, не закреплять проценты до проверки.
Не увеличивать фасад за счёт превращения правого визуала в миниатюру. Верхняя текстовая зона справа может занимать и область над навигацией, и область над медиа; не заставлять её всегда начинаться после отдельной широкой средней колонки. Нижние навигация и медиа компоновать общей CSS Grid со span/areas. Если жёсткие3 колонки не вмещают содержание, перераспределять области, а не уменьшать типографику и картинки.
Навигация расположена у границы фасада и правой сцены на спокойном белом поле; все3 названия и описания видны. Активный номер, тонкая бронзовая линия и один деликатный connector к фасаду связывают выбор со сценой. Connector иллюстративный, не техническое обозначение реального расположения лота. Не выдумывать точные этажи и соответствие выбранному апартаменту705 на картинке.
H2 — доминирующий двухстрочный элемент, абзац — следующий уровень, затем крупное медиа. Проверить чтение при100% zoom. Не считать одинаковыеx у всего экрана достаточным доказательством хорошей композиции: внутри своих зон нужны ясные опоры и один главный визуальный центр.
Правое медиа — крупное предметное доказательство. Представленный full-site screenshot содержит собственные шапки/кнопки/мелкий текст: сейчас они уменьшаются до нечитаемых. Все оригиналы сохранить. Для presentation допускается отдельное CSS-окно с контролируемым кропом пустой/служебной внешней шапки; не обрезать главный объект, план и важную карточку лота. Полный оригинал должен открываться по явному «Развернуть изображение» в доступном диалоге. Это предлагаемое оформление для review, не объявлять его ранее утверждённым решением владельца. Если подходящий кроп не получается, сохранить полный кадр и увеличить площадку медиа; не стирать интерфейс генератором и не пересоздавать fake controls поверх.
В эталоне есть диагональные границы; можно применить умеренную маску только к декоративной границе. Вшитые UI-подписи не должны теряться. Сохранить непрерывность фасада между3 состояниями. Правое медиа и зоны H2/абзаца имеют стабильную рамку: перемена текста не двигает остальные элементы. Убрать белый просвет, который появляется только ради невписавшегося min-height.

## Типографика — факты и ограничение
В текущем source @font-face загружает RF Dewi400/600/700 и Inter Tight variable. В браузере H1/H2 computed family RF Dewi. Это НЕ подтверждение утверждённой гарнитуры владельца. Прочитанные источники Twin не закрепляют точный новый шрифт. Название на растре также не доказательство. Не объявлять RF Dewi Expanded,Extended и обычный RF Dewi одним семейством.
Для первого технического прохода сохранять текущие local fonts, не вводить третью случайную гарнитуру; сравнить их характер с эталоном и вынести font-gap в итог отдельно. Если в актуальном репозитории уже появился прямой owner-lock с точным файлом — он приоритетен, использовать его и назвать источник. Независимую работу по композиции/motion не останавливать. Шрифтовая часть не получает PASS без подтверждения.
Размеры выводить из крупной и читаемой иерархии эталона с реальной шириной текста. Не задавать весь экран черезscale/zoom/letter-spacing ради втискивания.

## Остальная страница
Не удалять composition/delivery только потому, что в приложенном изображении короткая версия сайта. Проверить общие края и ритм переходов; сохранить рабочие якоря. Channels сейчас full-bleed фото с white-wash и текстом поверх: проверить контраст табов и абзацев на каждом кадре; при недостатке вынести текст на спокойную поверхность. Не расширять scope на новый продукт/backend.

## Адаптив
Desktop-сцена не должна отключаться целиком при высоте899px только из-за нынешнего media query min-height:900px: это распространённые ноутбуки. Для1440×900,1366×768,1280×800 обеспечить осмысленный вариант: компактный sticky если фактически вмещается, иначе содержательный native flow. При переходе не оставлять300vh пустоты.
На390/768px: вертикальный поток из3 сцен с полными текстами, контролируемый фрагмент фасада, крупное медиа; без tinydesktop, глобального horizontal scroll и вложенного scroll trap. Фото и UI не растягивать по одной оси.
