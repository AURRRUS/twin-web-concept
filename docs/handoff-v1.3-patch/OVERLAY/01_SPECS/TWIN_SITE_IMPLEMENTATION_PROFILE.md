# Профиль внедрения корпоративного сайта Twin

## P00. Назначение и статус
Пакет v1.2 подготовлен по решению владельца развить v1.1 и предусмотреть настоящий демонстрационный Twin. Это спецификация реализации, не готовый сайт. Содержимое и технология самого двойника пока не предоставлены. Общий стандарт — `../00_STANDARDS/TALENT_WEBSITE_DEVELOPMENT_MASTER_v1_1_2026-10-18.md`; профиль выбирает объём конкретного сайта.

## P01. Аудитория и задача
Девелопер и его коммерческая команда: понять продукт, самостоятельно проверить сценарий выбора, запросить показ на своём проекте. Демо недвижимости служит продаже Twin. Оно не становится публичным предложением покупки изображённого объекта.

## P02. Реализация по этапам
| Этап | Объём | Готовность |
|---|---|---|
| A — сайт и оболочка | Главная по концептам, `/demo`, адаптация, существующие диалоги, честная форма, контракт адаптера, резервный каталог | Можно реализовать на материалах пакета |
| B — реальное демо | Настоящий viewer, разрешённый проект, таблица соответствий, синхронизация выбранного лота, измерение загрузки и ошибок | Нужны материалы и технический интерфейс Twin |
| C — обращения | Серверная доставка, политика/согласие, выбранная CRM, повторы и журнал | Нужны endpoint, доступы и правила сопоставления |
| D — управление | CMS, проектное пространство, документы, ИИ, рабочая шахматка/аналитика | Отдельная детализация и оценка |

Этапы — предлагаемое распределение реализации; не договорная комплектация и не оценка сроков. Этап A не объявлять готовым реальным демо.

## P03. Матрица общего master
| Разделы | Применение |
|---|---|
| W04–W10, W25–W27 | Дизайн, mobile, состояния, доступность, скорость и QA — с этапа A |
| W06, W12–W13 | Единая модель выбора и покупательская шахматка — в границах разрешённого демокаталога |
| W14 | Контракт обращения с A; реальная доставка только C |
| W16–W21 | Расширение D; не обещать как уже работающую админку |
| W22–W24 | События, границы доступа и адаптер; фактические сервисы по этапу |
| W15, W29 | Реальная переоценка и экономика не входят в A/B |
| W30 | Сохраняет визуальную и содержательную преемственность |

## P04. Маршруты и контекст
`/` — история продукта; `/#product` — краткий встроенный обзор; `/demo` — рабочая демонстрация; `/#contact` — обсуждение проекта. Основной CTA «Посмотреть Twin» ведёт на `/demo`. Старые ссылки `#product` продолжают работать как якорь обзора. Форма получает доступный редактируемый контекст демо, но не блокирует обращение при его отсутствии.

## P05. Ограничения релиза
Не фиксируются этим пакетом: CMS/стек, технология viewer, объект пилота, реальные цены и источник наличия, CRM credentials, лимит нагрузки, стоимость и календарный план. Неизвестные значения — null/disabled, без фиктивных успешных операций. Наличие реального viewer не доказывает поддержку API выбора лота.

## P06. Выходы исполнителя
Код, инструкции запуска, таблица реализованных требований, реальные результаты QA, перечень недоступных возможностей, обновлённые статусы интеграций. Архив визуальных материалов не заменяет репозиторий кода.

## P07. Разработка частями и следующий ИИ-этап
Исполнение — по `TWIN_DELIVERY_PIPELINE.md` и W36 master. A–D обозначают объёмы продукта, TW-00, TW-D01…05, TW-M01…03, TW-A01…02, TW-I01…03 — отдельные пакеты работ. Первое задание — только TW-00; подготовка карточки TW-D01 входит в его выход. TW-A01…02/TW-I01…03 запускаются отдельным поручением, не автоматически после frontend. Новое направление корпоративной ИИ-среды — W35; не обещать эти функции как реализованные.

## P08. Последнее уточнение владельца
Разработка: desktop с дизайном → отдельная mobile-адаптация → админка → ИИ/автозадачи. Интеграции и вставка кода — W37 master. Конфигурация и публичные подключения закладываются до UI админки. Новая нумерация и порядок — в pipeline; старые упоминания TW-01…11 не использовать как действующий план.
