# Конкретные замены в коде и поведение

## 1. Journey: использовать готовое вычисление

Скопировать implementation/journeyFrameV3.mjs и journeyFrameV3.d.mts в src/lib/ рядом с journeyMotion.ts. В journeyMotion.ts заменить прежнее содержимое реэкспортом:

```ts
export { clamp, journeyFrame, createProgressDriver, sceneTargets } from './journeyFrameV3.mjs';
```

Существующий Journey.tsx сохраняет импорт из journeyMotion, запись CSS-переменных, dataset и работающие layoutMode/motionEnabled. Не переписывать компонент целиком. Не запускать вторую timeline поверх модуля. Typecheck обязателен после интеграции.

Чистый модуль использует те же ключи titleOpacity/titleY/titleClip/bodyOpacity/bodyY/mediaOpacity/mediaScale/mediaY/active/title/explanation. Корректность формул проверена отдельно. Поведение DOM, clipping и фактические размеры исполнитель проверяет в браузере.

## 2. Переход вместо исчезновения содержания

Сохраняем usefulScroll280 svh при host380 svh/panel100 svh, когда композиция помещается. Holds: project0–.20, space .45–.60, lot .85–1. Локальные переходы .20–.45 и .60–.85:

| Локальный q | Что меняется |
|---|---|
| .04–.32 | Старый/новый заголовки: взаимодополняющий crossfade, старый Y0→-8 px, новый18→0 px |
| .30–.58 | Описания: аналогичный crossfade, старый остаётся до вступления нового |
| .60–1 | Новый лист: scale1.08→1, Y-48→0 px |
| .60–.76 | Opacity нового листа0→1 поверх старого |

В каждый момент сумма opacity старого/нового заголовка равна1; аналогично описанию. Базовое изображение остаётся видимым. titleClip в модуле0: не накладывать прежнюю маску, которая снова съест оба текста. Текстовые слои занимают один измеренный слот; переход не должен превращаться в длительную нечитаемую смесь строк. Если в браузере пересечение плохо читается, сократить интервал crossfade до локальных .08–.24, сохраняя комплементарные opacity и ранний заголовок; не возвращать фазу «оба0».

Фасад и навигация неподвижны. Новое медиа целым слоем укладывается сверху, старый лист под ним. Маски/overflow ограничивают только выделенную область медиа, не весь текст. Никаких тени, вращения, общей прозрачности родителя или заменыimg src посреди движения.

Сглаживание нового driver —220 ms вместо 60 ms. Нет порога target-current>.30, мгновенно перескакивающего крупный переход. snap используется только при init/переконфигурации, а не при каждом scroll. Колесо не блокировать. На быстром уходе из сцены/якорном переходе разрешено явно settle/snap при необходимости доступности, но обычная прокрутка не должна вызывать скачок.

Первое состояние при подходе к разделу тоже раскрывается каскадом. В текущем Journey.tsx событие twin:settle-reveal при atPin преждевременно гасит входную анимацию. Не отменять всю entry-хореографию просто из-за rect.top<=0; завершать её по фактическому окончанию, либо сразу собрать первый кадр только при прямом якорном прыжке/восстановлении позиции. Не держать users в скрытом первом кадре.

## 4. Треугольник

Оставить уже реализованные 420 svh/100 svh/useful320 svh, не удлинять ещё раз. Проверить, что motion реально включён на рабочем desktop; dataset.enhanced=false означает статическую альтернативу, наличие CSS420 svh не доказывает анимацию.

Фазы: .00–.08 вводная; .08–.18 ответ; .18–.30 две стороны+срок/цена; .30–.42 третья сторона; .42–.52 модель+демо; .52–.72 hold с«Эффектно»; .72–.84 вставка«ив»; .84–1 finalhold. SVGлиния и появление модели не должны завершаться в первых20%сцены. Проверить фактический deliveryFrame, а не толькоhostHeight.

Срок/стоимость — сохранённые показатели, не счётчики. Слово реальное: «Эффект»+«ив»+«но», ширина финального слова резервируется по Semibold 600; вставка не сдвигает соседние слова. Ссылкаdemo доступна, не нужно прокрутить доp1 для возможности нажать её.

## 5. Ограничения

Без перехвата wheel, навязанных scroll-snap, бесконечной суеты, blur текста и заставки перед чтением. При reduced-motion всё доступно без transforms/pin. На mobile короткое появление<=400 ms,scale<=1.02, без длинныхpinnedсцен. На низкомdesktop отключениеpin сохраняет композицию и кнопочный выбор. No-JS/failure не скрывает контент. JS cleanup/resize/повторныйmount не создают дублирующиеobserver.
