# Задание: стройная сетка и два верхних экрана

## Результат
Первый экран читается по двум смысловым строкам и использует новый чистый фон. Во втором — постоянный вертикальный фасад слева, вертикальная навигация в центре, крупная сцена справа с меняющимся заголовком над ней. Три состояния: проект → пространство → лот. Переход заголовка опережает переход изображения.
«Отцентровать» означает центрировать общий контейнер страницы. Текст остаётся выровнен по левой границе своей колонки. Не центрировать каждый элемент независимо.

## 1. Единая система привязок
Сохранить существующие основные токены: content-max 1408px; desktop gutter clamp(40px,4.444444vw,64px). В вычислении использовать ширину layout viewport без полосы прокрутки.
Обозначим W ширину доступного layout, G gutter, C=min(1408px,W−2G), L=(W−C)/2, R=L+C. Контейнер ровно между L и R. На телефоне G=20px; от 601 до 950px G=32px; от 951px — desktop формула. Один reusable container, не отдельные проценты для каждой секции.
Шапка: видимая левая граница логотипа, а не прозрачный край PNG, совпадает с L; правая граница CTA совпадает с R. Оптический inset допускается только как документированная компенсация прозрачного поля логотипа. Не сдвигать текст на случайные 32px из-за логотипа.
Hero: H1, абзац и начало ряда CTA лежат на L. Базовая линия вторичного CTA согласована с основным. Навигация шапки имеет свой измеримый столбец и не висит между произвольными процентами.
Второй блок: все внутренние границы получены из одного grid. Заголовок справа, пояснение и рамка правого изображения имеют одну левую границу; их правый край ≤R. Фасад можно тянуть к левому краю viewport как осознанный full-bleed, но его правая граница — линия общей сетки. На десктопе правое медиа не упирается в край viewport: придерживаться R.
Измеряемая допустимая погрешность общих привязок ≤2 CSS px. Во вложенных карточках разрешены явные внутренние padding; измерять отдельно контейнер и контент.
Не добиваться совпадения transform:translateX, отрицательными margin или россыпью left:44%/49%. Свести существующие конфликтующие CSS-переопределения в одну схему.

## 2. Hero
Ассет hero — по manifest. Изображение чистое, надписей в файл не добавлять. Вся типографика, CTA и логотип остаются DOM/оригинальным логотипом.
Desktop от 1280px: ровно две строки H1:
Цифровая инфраструктура продаж
девелоперского проекта.
Точка сохранена из текущей копии; не переписывать позиционирование. Убрать старые три span-строки. При 951–1279px допустим семантический перенос на 3 строки: «Цифровая» / «инфраструктура продаж» / «девелоперского проекта.»; на мобильном естественные переносы, без горизонтального скролла. Не разрывать «продаж девелоперского» в самостоятельную строку.
Для 1280–1920px стартовый диапазон H1 44–64px, line-height 1.08–1.12. Итоговую величину выбрать по фактическому шрифту: сначала расширить текстовую область в спокойную часть неба, затем аккуратно настроить размер. Не ужимать буквы scaleX и не уменьшать ниже44px ради двух строк. Если истинная гарнитура не помещается — показать измеренную причину, не подменять её. Задача двух строк требует перераскладки композиции, а не сохранения старого max-width:85% автоматически.
Абзац сохранить: «Раскрывайте преимущества проекта и помогайте покупателю выбирать — на сайте, дистанционно, через агентов и в офисе продаж.» Ширина 440–520px, 18–20px desktop; 16px mobile. От H1 24px, до CTA 32px; CTA gap24–32px.
CTA сохранить: «Посмотреть Twin» → текущий маршрут демо; «Обсудить проект» → контакт. Сохранить маршрутизацию sitePath/base path.
Hero фоновый cover; подобрать object-position по размерам, сохранить главное здание и морской контекст. Не растягивать по одной оси. Спокойная верхняя область нужна для H1: не заливать весь курорт непрозрачным белым. Допустим локальный мягкий wash только для читаемости, проверить контраст. Удалённый владельцем декоративный элемент слева не возвращать.
Высота под контент, ориентир desktop min-height clamp(680px,90svh,1000px); на низком экране разрешить естественное увеличение, не обрезать CTA. Не оставлять огромную пустоту только ради заполнения экрана.

## 3. Второй блок: desktop
Режим трёх колонок с 1280px, если высота≥800px; для более низких viewport использовать статический вариант с сохранением трёх смысловых состояний.
Сетка внутри C: gap24px, колонки minmax(0,3fr) minmax(150px,1.5fr) minmax(0,7.5fr). Это конкретный старт реализации, не требование сохранить старые проценты. Правая колонка получает основную площадь для изображений с UI. На контрольных размерах проверить читаемость, отсутствие пересечений. При необходимости корректировать пропорции целиком через grid-template-columns и фиксировать в отчёте.
Слева: большой вертикальный фасад, постоянный во всех трёх состояниях. Сохранять вертикальность, cover допустим; не зажимать в маленькую карточку. Не генерировать другую архитектуру. Full-bleed разрешён только слева от этой колонки.
В центре: одна вертикальная группа из кнопок 01 Проект, 02 Пространство, 03 Лот, сверху вниз. Активность видна цветом/линией и aria-pressed. Не превращать в горизонтальные табы над изображением. Весь блок управления в пределах своей колонки; подписи не заходят на фасад/медиа.
Справа: меняющийся H2 над неизменной по положению рамкой медиа, далее краткое пояснение. Зарезервировать одинаковую высоту зоны H2 по максимальному заголовку; смена текста не двигает рамку. Высоту рамки вычислять из доступной высоты, сохранять разумный aspect-ratio около16/10; все три исходника — contain, целиком, на спокойном фоне. Поскольку UI уже запечён, обрезать края нельзя. При различии пропорций допустим воздух внутри общей рамки, а не растяжение.
Область контента имеет вертикальные padding48px, промежуток заголовок→медиа24px, медиа→пояснение16px. Если полная сцена не помещается по высоте, переходить к статическому варианту, а не обрезать изображение.
Не накладывать имитации hotspots/цен/кнопок на запечённый UI. Это презентационные изображения, не реальная интеграция.

## 4. Содержание трёх состояний
| Состояние | H2 | Пояснение | Ассет |
|---|---|---|---|
| Проект | Покажите, что делает проект ценным. | Окружение, архитектура и инфраструктура — в едином представлении проекта. | scene-project |
| Пространство | Дайте почувствовать пространство. | Покажите пространство внутри проекта и вид из будущего лота. | scene-space |
| Лот | Раскройте конкретный лот. | Свяжите выбранный лот с корпусом, этажом и планировкой. | scene-lot |
Первый H2 уже принят в переписке. H2 и пояснения для2/3 — рабочая копия для реализации, не объявлять их отдельно утверждённым рекламным каноном. Не расширять обещания продукта. Метки Проект/Пространство/Лот сохранять.
По supplied files: space показывает вид с балкона; не обещать, что в этом PNG содержатся все общественные зоны/интерьеры. Lot — план этажа с интерфейсом, не полноценная интерактивная3D-модель.

## 5. Адаптив и неизменность продукта
До1280px и при малой высоте — читаемая статическая последовательность из трёх пар заголовок+изображение, без длинного sticky spacer. Фасад на мобильном отдельным вертикальным фрагментом высотой до360px; не ставить его полноэкранным барьером перед содержанием. Навигация может стать компактным списком якорей; не требовать трёх колонок на390px. Все сцены доступны без JS, sticky или движения.
Нижние секции проверить только на последствия общих токенов. /demo/: сохранить выбор корпус/этаж/лот, вкладки и параметры URL, сообщение об отсутствии настоящего Twin. Новые PNG не означают появление настоящего API, цен, наличия и новых лотов.
