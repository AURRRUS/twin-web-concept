# Материалы владельца
Все пять PNG из «Финалка для демо.rar» приложены побайтно. Ключи/размеры/SHA256 — в manifest.json; визуальная сверка — ASSET_INDEX.html.

| Ключ | Исходный файл | Назначение и обработка |
|---|---|---|
| hero | Роскошный апартамент с видом на море.png | На самом деле широкий чистый курорт: фон hero, cover, без вшитых букв |
| facade | 12 ти этажный корпус.png | Вертикальный фасад слева во втором блоке, cover |
| scene-project | Роскошный курорт у моря_ инфраструктура и резиденции 1.png | Аэропанорама инфраструктуры с уже нарисованным UI, contain |
| scene-space | Вид побережье.png | Вид с террасы/балкона с уже нарисованным UI, contain |
| scene-lot | План этажа 12 ти этажного корпуса.png | План этажа с уже нарисованным UI, contain |

В правых трёх PNG есть MORE RESIDENCES, подписи, элементы управления, номера и цена. Это часть supplied mockup. Не выдавать их за действующие данные Twin; добавить короткую DOM-подпись «Иллюстрация интерфейса. Данные демонстрационные.» Не копировать цену и номера в работающие поля демо. Не рисовать сверху второй комплект шапок/кнопок. Не удалять запечённый бренд/интерфейс автоматически и не генерировать замену без задачи.
Отдельной чистой3D-планировки в этом архиве нет. Текущее решение для третьего состояния — приложенный план этажа. Полноценная3D-планировка/переход внутрь лота требует другого исходника/реальной интеграции, это не входит в задачу.
Можно создать оптимизированные webp/avif производные, сохранив PNG как оригиналы и карту соответствия. Интерфейс на картинках должен оставаться резким; не применять агрессивное сжатие и tint/mix-blend-mode. Для hero eager/preload только одного нужного варианта, остальные изображения декодировать до перехода, не грузить все тяжёлые PNG синхронно.
Пути назначения рекомендуется public/media/top-v2/{hero,facade,project,space,lot}.webp. Обновить src/lib/media.json/Media, не хардкодить неверный root URL: сайт размещён под /twin-web-concept/.
