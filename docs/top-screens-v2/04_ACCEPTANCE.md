# Приёмка реализации
Не писать «выровнено» без измерений и просмотра результата. Проверять реальный собранный сайт после загрузки fonts/images.

## Матрица
Viewport:390×844,768×1024,1024×768,1280×800,1440×900,1920×1080. Дополнительно desktop низкой высоты1440×700. Обычный и prefers-reduced-motion. На каждом размере нет горизонтального overflow, пересечений, обрезанного H1/CTA.
Для L/R использовать document.documentElement.clientWidth, не смешивать с outerWidth/шириной скриншота. Точность общих краёв2 CSS px.

## Обязательные подтверждения
- [ ] Все5 ассетов сверены по manifest, нет подмены stock/imagegen.
- [ ] На1280/1440/1920 H1 две строки в точном смысловом разбиении. На узких экранах читабелен, не мельче заданного.
- [ ] Логотип визуальным краем, hero текст и CTA имеют общую L; общий контейнер центрирован; header CTA наR.
- [ ] H2, пояснение и рамка медиа второго блока имеют общую левую/правую опору. Снять x/width для этих трёх элементов.
- [ ] На desktop фасад большой вертикальный слева, навигация вертикальная в центре, сцена справа. Нет горизонтальных табов вместо средней колонки.
- [ ] Рамка сцены стабильна: при смене трёх H2 и media её x,y,width,height не скачут более2px.
- [ ] Скриншоты P=.10,.50,.90 и переходов P=.25,.30,.35,.65,.70,.75 показывают каскад. Приq=.40 новый заголовок ужеopacity1, старое изображение ещёopacity1.
- [ ] Медленный/быстрый/обратный скролл, прыжок1→3 и3→1 дают правильное состояние без очередей и пустых сцен.
- [ ] Все3 UI-изображения видны целиком и без дублирующих controls. Подпись о демонстрационных данных есть в DOM.
- [ ] Клавиатура, reduced-motion, отключённый JS и низкий экран сохраняют доступ к содержанию.
- [ ] Сетевые запросы fonts успешны; кириллица и начертания действительно отрисованы нужными файлами. computed font-family сам по себе не доказательство.
- [ ] /demo/ загружается; выбор/вкладки и параметры projectId,buildingId,floorId,lotId,view сохраняются в тех сценариях, где работали до правок. CTA/контакт и возврат работают под base path.
- [ ] Нижние секции не сломаны общими токенами.

## Что сдать
1. Название исходной/рабочей ветки и commit SHA, что изменилось.
2. Команда запуска/локальная ссылка либо доступный preview согласно разрешениям репозитория.
3. Скриншоты до/после первого и второго блоков на1440 и390; три финальные сцены и хотя бы один промежуточный каскад.
4. grid-measurements.json или таблица: viewport/layoutWidth,L,R,селектор,x,right,width,ожидаемая привязка,отклонение. Значения реально измеренные, не расчёт вместо наблюдения.
5. Реально выполненные build/lint/существующие релевантные Playwright-проверки по package.json. Дополнить существующий desktop/motion тест проверкой значимого контракта каскада/геометрии, не писать десятки зеркальных snapshot-тестов.
6. Честно отметить невыполненное. Одна успешная сборка не подтверждает качество вёрстки.
