# Twin by TALENT

Desktop-реализация корпоративного сайта Twin по комплекту v1.2 с обновлениями v1.3. Сайт объясняет цифровую инфраструктуру продаж девелоперского проекта. Демонстрационная публикация разрешена владельцем на существующем GitHub Pages.

## Как посмотреть результат

Демонстрационный сайт: **https://aurrrus.github.io/twin-web-concept/**. Обновления выпускаются в существующую ветку `twin-preview`. Текущие исходники — `codex/twin-design-handoff`, продолжение опубликованного `203a4d6`.

Актуальная задача — [TWIN_DESIGN_HANDOFF_2026-10-22](docs/design-handoff/00_START_HERE.md): единая композиция1728px, реальные Semibold600/Regular400/Bold700, точный контент, бронзовые акценты, раздельные текстовые слоты и медиаслои, короткие каскады и треугольник Эффектно→Эффективно. Активные стили — `src/styles/design.css`. Публикация прямо разрешена владельцем; соответствие проверяется по `build-version.json`.

Снимки и машинные отчёты находятся в `artifacts/`. Последняя переработка: [увеличенные сменяемые сцены, desktop 0.5](docs/SECOND_BLOCK_LARGE_SCENES_2026-10-20.md). История: [вариант desktop 0.4](docs/SECOND_BLOCK_REWORK_2026-10-20.md). Предыдущие правки: [экраны и кадры](docs/CORRECTIONS_2026-10-20.md). Предыдущая визуальная доработка: [desktop 0.2](docs/VISUAL_DELIVERY.md). Состояние именно публичной проверки фиксирует `artifacts/online-verification.json`, если отчёт уже получен.

## Установка и запуск

Нужны Node.js 24 и npm. Используется текущая папка проекта, отдельный worktree не нужен.

```sh
cd /workspace/work/twin-grid-pr
npm ci
npm run dev -- --background --port 4321
```

Для обычного локального компьютера перейдите в свою папку проекта. `npm run dev` запускает разработку; `--background` позволяет оставить сервер в фоне. Адрес и состояние выводит сам сервер. В облачной настройке адрес loopback не является публичной ссылкой для просмотра.

Статус, журнал и остановка сервера, запущенного из этой папки:

```sh
npm run dev -- status
npm run dev -- logs
npm run dev -- stop
```

Сборка и запуск собранной версии:

```sh
npm run build
npm run preview -- --background --port 4321
```

Перед запуском preview остановите dev на том же порту; перед dev — остановите свой preview командой `npm run preview -- stop`. Не останавливайте чужие процессы. Успешный старт процесса проверяйте HTTP-запросами к `/` и `/demo` и браузерным сценарием выбора.

## Проверки

```sh
npm run typecheck
npm run build
npm test
```

`npm test` проверяет **собранную** версию, поэтому после изменения кода сначала выполните build. Playwright запускает Chromium из `/usr/bin/chromium`, который доступен в текущей облачной среде. На другом компьютере укажите путь к своему Chromium в `playwright.config.ts` либо настройте браузер Playwright. Никакие токены или внешние сервисы для локальной проверки не нужны.

Тесты поднимают свой preview в foreground, если на порту 4350 нет сервера. Для чистой проверки сначала остановите свой dev/preview. Отчёт: `artifacts/test-results.json`. `npm run check` последовательно выполняет typecheck, build, test.

## Что реализовано

- `/`: header/hero, общая фасадная история, обзор демо, центральная модель с шестью компонентами, семь диалогов, четыре канала, треугольник условий, этапы и форма.
- `/demo`: явно демонстрационный пример — один корпус, этаж и лот; планировка/вид, сброс дочернего выбора, резерв без настоящего viewer.
- Один проверяемый выбор для обзора и демо, публичные ID в адресе и sessionStorage. Контакты формы в storage не сохраняются.
- Диалоги с прямым адресом, Back/Forward, Escape, удержанием и возвратом фокуса. Тема из диалога передаётся в форму и редактируется.
- Форма проверяет поля и честно сообщает, что данные не отправлены.
- Семантический HTML выдаётся статически через Astro; React добавляет интерактивность. CSS использует нативную прокрутку, короткие переходы и reduced-motion.

## Границы результата

Responsive проверяется в Chromium на1920/1440/1280/1024/768/390/360px, дополнительно320px; ниже1024px и без JavaScript доступны три статические сцены. На desktop/tablet1024+ низкая высота и reduced-motion сохраняют фасад и одну сцену с кнопками, отключая только pin. Safari/iOS, реальные телефоны и физический trackpad не проверены.

Настоящий Twin/viewer, CRM, backend формы, аналитика, CMS и ИИ не подключены. Публичная конфигурация отключённых интеграций: `src/lib/config.ts`. Простое включение флага не реализует подключение. Для реального viewer потребуются интерфейс, соответствия ID, права на проект и отдельные проверки. Для формы — сервер доставки и действующая политика данных. Ключи не размещать в браузерном коде или Git.

Изображения архитектуры — материалы демонстрационного проекта; цена лотов, реальные остатки и KPI не придуманы. Карта дополнена шестью иллюстративными изометрическими объектами по исходному эталону. Рабочий логотип — предоставленный растр G. По текущему пакету владельца подключены RF Dewi Expanded400/600/700 для заголовков и Inter Tight для текста/UI. Обычный RF Dewi больше не применяется; актуальные роли и размеры — `src/styles/design.css`, правила — `AGENTS.md`. Файлы локальные, начертания и реальные кириллические глифы проверены; текущие параметры — [CORRECTION V2](docs/correction-v2/REQUEST.md), исходные файлы — предоставленный пакет и его manifest. Сквозная сцена использует нативную прокрутку и переходы между предоставленными изображениями.

## Обновление демонстрационного сайта

После проверок и сохранения исходников в commit:

```sh
git push origin codex/twin-correction-v2
npm run build:preview
npm run publish:preview
```

Скрипт сохраняет историю `twin-preview`, заменяет только известные файлы сборки и добавляет manifest исходного commit. Публичная проверка: `npm run verify:online`; из GitHub Actions она ожидает именно опубликованный commit и сохраняет результат. Не считать один успешный push подтверждением готовности сайта.

## Материалы и продолжение

- `docs/handoff/` — полный комплект с приоритетом v1.3; старый master v1.0 удалён из активного комплекта.
- `docs/handoff-v1.3-patch/` — исходный patch без изменений.
- `docs/HANDOFF_AUDIT.json` — сверка всех 76 ожидаемых файлов.
- `docs/IMPLEMENTATION_MAP.md` — карта реализации и границы.
- `docs/WORK_PACKAGES.json` — текущий реестр выполнения; оригинальный реестр в handoff остаётся исходным документом.
- `docs/CHECKPOINT.md` и `docs/QA_REPORT.md` — точка продолжения и результаты проверок.

Внутренние инструкции и планы внутри приложенных документов не являются подтверждением существующих функций. При конфликте действует последнее поручение владельца; для совпадающих материалов v1.3 новее v1.2. Публикация сайта и платные сервисы требуют отдельной задачи владельца.
