# Композиция второго экрана
Сверху — один меняющийся заголовок, две смысловые строки по content.json. Рубрика, счётчик 02/04, внешняя подпись и «Развернуть» удалены. Заголовок не разрывать посреди смыслового словосочетания.

Ниже — единый контейнер max1728px и поля layout. Desktop: левая колонка 25% доступной ширины, gap28px (40px на широком экране), правая — оставшаяся ширина. Слева четыре состояния в обычном потоке. Активное раскрыто в бронзовую карточку с белым текстом: название, одна простая контурная иконка, две метки и пояснения. Внутренние поля24px, промежуток между смысловыми группами16px, radius6px. Закрытые строки — текст и тонкая линия, целевая зона минимум44px; не делать четыре массивные pill-кнопки.

Размеры получают из ролей. На desktop support18/28, navigation18/28, section48/58, card24/32; на широком согласно таблице. На низком desktop допустим section38/46 как явно документированное исключение задачи, остальные тексты не сжимать. Если содержимое не помещается с резервом по высоте, отключить pin и дать обычный поток/switch. Сначала измерить реальные bounding boxes после загрузки шрифтов, затем выбрать режим.

Справа — стабильная крупная рамка с оригинальным UI. Изображение contain, intrinsic aspect-ratio из файла, без декоративной пустой полосы и обрезания интерфейса. Frame не прыгает между сценами; сначала preload/decode всех четырёх, не показывать пустой кадр при быстром переключении.

При ширине меньше1100px переходить к одноколоночной композиции: общий заголовок, состояния; открытая группа включает пояснения и своё изображение. Изображение следует за связанным текстом, а не остаётся далеко внизу. Никакого desktop pin на телефоне. Контент доступен без JS; управление доступно с клавиатуры и имеет aria-expanded/controls. Активность обозначается цветом и раскрытием, не только цветом.

Критерий: за один взгляд видно, какой режим открыт, зачем он покупателю и чем помогает команде; следующий взгляд попадает на большой реальный интерфейс. Не добавлять декоративную информацию, которая конкурирует с этой связкой.

Проверенная настройка исполнения: внешние desktop-поля по вертикали32px. При 1440×900 весь контент требует880px с запасом24px и помещается; при 1280×720/1366×768 включается flow-switch без уменьшения шрифтов и кадра. Эти значения — фактическая проверка Chromium в CSS viewport, не физических устройств.
