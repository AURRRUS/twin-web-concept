## Сквозная система

1. **Типографика.** Реальные RF Dewi из `src/assets/fonts`, без synthetic bold/scaleX. V1 `src/styles/design.css` действительно содержит Expanded Black900, Semibold600 и Inter Tight variable; WhatFont-снимок не является выдуманным alias. Одобренные синие области служат донорами конкретных ролей hero/menu/CTA; это не разрешение заменить весь RF Dewi на Inter, особенно Journey. Второе ТЗ фиксирует числовые роли/диапазоны, line-height, tracking, measure и safe zones. В каждом H1/H2 один ясный смысловой акцент бронзой, без конечных точек и висящих коротких слов.
2. **Глубина.** Белый не запрещён. Отвергнута одинаковая пустая подложка без сцены. Использовать существующие архитектурные/предметные слои, тёплую каменную поверхность, линии и двухмасштабные тени по эталону. Текст/контролы остаются DOM; фон страницы не превращается в единую картинку. CSS/SVG для линий, масок и теней —0генераций.
3. **Scroll.** Найден реальный инженерный донор: V1 `useStoryTrack.ts` + `salesStoryFrame.mjs`/`salesStoryMotion.json`; ещё один — `useJourneyV456.ts` + `journeyV456Frame.mjs`/`journeyV456Motion.json`. Там отдельные read/transition-интервалы, независимое раскрытие title/body/image, reverse и nav-targets. Нынешний V2 делит короткий путь960–1440px на4мгновенных active-квартала и отключает pin при oversized panel. Это подтверждает техническое отличие, но не доказывает, какой именно ранний вариант владелец счёл удачным. Переиспользовать принципы/чистые функции адресно, не весь старый layout. Полноценный motion-план — во втором ТЗ: координаты начала/конца, travel в px/viewport, holds, переходы, параллакс только доступных слоёв, jump/reverse/resize и reduced-motion.
4. **Конверсия.** Маршрут: ценность → выбор → демонстрация → состав → сценарии → условия → запуск → обращение. Прямой переход к demo/обсуждению доступен без прохождения всех эффектов. Пауза удерживает понятную сцену, не блокирует wheel/touch и не растягивает десятки фото.
5. **Ассеты.** У каждого заказа источник, защищённый объект, слой/alpha, crop/anchor, CSS-size/target pixels, camera/light, причина усиления, лимит попыток, сценическая приёмка. Маска не создаёт отсутствующие пиксели. Никаких30картинок до принятия одной сложной пробы.

## Партии и приёмка

- **Сейчас:** шапка/hero + Journey, сохранить принятый стык. Исходники остальных компонентов/CSS и ассетов защитить baseline-хешами; новый motion не должен тянуть их за собой.
- **После принятия первой пары и отдельной команды:** видео + основа; затем каналы + качества; затем запуск + финал. Размер партии можно уменьшить до одного сложного блока, не увеличивать молча.
- Web Production связывает решения и задачи; Frontend реализует; Code Motion задаёт числовое поведение; отдельный reviewer сравнивает реальный браузер с эталоном/контрактом. Финальный owner — владелец.
- Desktop1440×900/1366×768/1920×1080, mobile390×844/360×800, границы768/1024/1099/1100, keyboard/reverse/re-entry/reduced-motion. Не уменьшать весь экран до нечитаемости ради fit. Оценка hold-паузы требует реального ввода; screenshots/build не доказывают motion.
- Перед выдачей: независимые composition/type/material/mobile verdict, функциональные проверки, точный source и постоянная ссылка. Technical PASS, internal visual verdict, owner acceptance и deploy — разные статусы. Публикуется разрешённый рабочий preview этой V2; исходный V1 сохраняется.

## Открытое и реализуемость

Композиция, рамки, слои, крупное медиа и управляемый scroll реализуемы в текущем стеке; смена фреймворка не нужна. Сходство зависит от правильных исходников и геометрии, а не числа анимаций. Открыты сам видеофайл, финальный core-кандидат, новые лаконичные названия/иконки Journey и зеркальный финал. Команда предлагает и визуально проверяет их в соответствующей партии. Эти решения не блокируют работу над текущими первыми двумя экранами.
