# VIS-004 — как реализовать выбранный Twin V2
Режим: подготовка производства. Источник кода: d487775168f9e45dff45871fe6e2553fe162e924, work/twin-v2. Изображения владельца осмотрены 27.10.2026; новые reference-upper.jpg/reference-lower.jpg в этой папке — JPEG-копии без изменения размеров. Исходные PNG: 841×1870 и 891×1766. Library originals: libfile_648488a130c08191963e451244a5dfa0 и libfile_9dc3242904cc819182fe6d8e43147e7c.
В этом проходе проверены изображения, исходный код и выбранные исходные ассеты; live browser и новые генерации не выполнялись.

## Вывод
Реализуемо в текущем Astro/React. Большая часть визуального языка — композиция DOM/CSS/SVG и точная работа с изображениями; сложная пространственная связка hero/Journey требует подготовленного материала. Новый framework или полноценная 3D-сцена для декоративного эффекта не нужны. Настоящий интерактивный viewer и отправка формы — отдельные интеграции.
Сохранить V1 и существующий /v2/, не создавать V3. Поведение и данные можно переиспользовать; композицию прежних секций нельзя считать ограничением нового дизайна.

## Какие решения остаются выше картинки
Journey бело-бронзовый с тёмным текстом; без двух колонок «Покупателю/Команде». Заголовок «Покажите, почему стоит выбрать ваш проект»; внутренние состояния описывают покупателя. Центр состава — весь Twin проекта, не квартира. RF Dewi Expanded в крупных заголовках, RF Dewi в UI. Бронзовые акценты, никаких конечных точек и висячих предлогов. Без засветления hero.
Обзор содержит старые тексты, цвет карточки, логотипную перерисовку, выдуманные UI-надписи и модель квартиры в составе — их буквально не копировать. Взять масштаб/плоскости/глубину/связи, использовать точные исходники.

## Фактически проверенные исходники
- public/media/top-v2/facade.webp: 1024×1536, RGB, без alpha. Это отдельный фасадный ракурс с небом/морем, не готовый foreground для hero. Не подменять им слой другого ракурса
- public/media/composition-core-20261023.png: 1448×1086, paletted PNG с прозрачностью. После RGBA conversion alpha 0…254, visible bounds [21,67,1411,930]. Модель нескольких корпусов и территории; пригодна как исходник состава. Не масштабировать по всей рамке, игнорируя прозрачные поля
- src/components/v2/FullPage.tsx подключает прежние ProductDemo/Composition/Channels/Delivery/Launch/ContactForm. В src/styles/v2/full-page.css отдельные локальные стили. Следующий redesign должен менять геометрию и отношения, а не только оттенки
- Реальные RF Dewi 400/600/700 и Expanded 400/600/700/900 есть в production manifest; отсутствие шрифтов не является текущим блокером

## Три необходимых пакета
1. Инженерный: один reference viewport, 6 основных ролей (hero/section/item/body/control/caption), разрешённые responsive значения, ширины набора/переносы, сетка, роли поверхностей/теней и подробная таблица геометрии каждой сцены. Точные числа выбрать после набора реального текста настоящим RF Dewi; не снимать кегль OCR с растра и не менять гарнитуру
2. Графический: hero master+foreground+clean plate, при необходимости тень/грань; четыре изображения этапов запуска; адресные исправления каналов только после осмотра. CSS-панели/треугольники/линии не генерировать
3. Поведение и приёмка: схема диапазонов каждого motion, свободный выход из sticky, reverse/holds/click, mobile и reduced-motion; сравнение по масштабу/интервалам/глубине/читаемости. Проверять обычную прокрутку, а не только anchors

## Порядок исполнения всей страницы
A. Закрепить инженерную композицию всей страницы и подготовить недостающие слои. Проверить первый пространственный переход в короткой кодовой сцене без полной сборки: это снимает главный риск, scope остаётся всей страницей.
B. Собрать статичную полную V2 по общей системе: сначала связка hero/Journey, затем рабочая сцена, состав/каналы/качества/запуск/финал. Не переносить старые styles как визуальный канон.
C. Сделать mobile отдельной композицией: читаемый поток, активная карточка рядом со своим медиа, без desktop pin-tracks и разрезанного заголовка. Desktop-изображение не является mobile reference.
D. Включить уже спроектированный motion: сначала Journey и stack каналов, затем спокойные входы/треугольник. Текст не должен двоиться, сцены не блокируют scroll.
E. Отдельно проверить визуал и функции; исправить расхождения; выпуск /v2/ с сохранением V1 по отдельному execution-контракту. Подготовка не является командой немедленно запускать Codex.

## Что не делать
Не новый архив общих слов. Не полный тройной апскейл всего сайта. Не генерировать все изображения заново. Не снижать художественные требования ради reuse. Не объявлять quality gate доказательством совпадения. Не делать целую страницу фоновой картинкой.
