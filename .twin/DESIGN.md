# Оформление Twin
Источник чисел — tokens.json; реальные файлы и контрольные суммы — assets.json. Таблица для чтения генерируется в TYPOGRAPHY.md, CSS — generated/tokens.css. Изменять источник, затем `npm run twin:tokens`; проверка не переписывает источник.

Система сейчас предназначена для новых и явно мигрируемых компонентов, прежде всего JRN-001. Она подключена к новой основной секции JourneyAccordion в JRN-001; остальные секции сохраняют прежние стили. Инженерные значения проверены структурно, визуальное утверждение остаётся отдельным результатом.

RF Dewi и RF Dewi Expanded — разные реальные семейства. Размер, weight, leading и tracking берутся всей ролью; не подменять Expanded обычным и не сжимать scaleX/stretch. Никакого синтетического bold. Запрещены отрицательный tracking и line-height меньше роли без отдельного записанного исключения. Текстовое слово Bold не является спецификацией файла.

Использовать роль section для заголовка секции, card для заголовка карточки, navigation для переключателя, body/support для пояснений, label для меток, button для действия. Бронза выделяет активное состояние и смысловой акцент, а не каждое слово. Группировать заголовок и пояснение, не разносить связанный смысл по краям экрана.

Импортировать generated/tokens.css по исходному пути в затронутом компоненте; относительные URL шрифтов рассчитаны на этот путь. Обернуть новый экран в `.twin-system`; роли использовать `data-type`. Переменные имеют префикс `--ts-`, чтобы не менять старый сайт глобально.

Одна система направляющих: контейнер max1728px, поля по breakpoint, интервалы по layout. На низком окне менять композицию, не сплющивать шрифт. На мобильном читать сверху вниз, без многоэкранной scroll-ловушки. Изображение product UI сохраняет исходное соотношение сторон и содержимое.

Урок JRN-001: на цветной карточке задавать семантический color непосредственно текстовому элементу, если общие p-правила сайта могут перебить наследование. Проверять фактический цвет в браузере; одного цвета родителя недостаточно.
