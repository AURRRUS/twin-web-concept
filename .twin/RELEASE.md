# Выпуск
1. Сверить актуальный canonical head и live sourceCommit. Сохранить remote backup refs исходников и текущей Pages-ветки с уникальным именем; не двигать старый резерв.
2. Выполнить приёмку. Изолированный diff должен соответствовать scope. Незавершённая параллельная работа не попадает в выпуск.
3. Использовать существующий проверенный build/deploy проекта. Не менять настройки Pages и не создавать новый способ сборки без причины. Документация системы сама сайт не публикует.
4. После записи release commit публиковать разрешённую задачу, проверить live sourceCommit, загрузку шрифтов/ассетов и ключевой сценарий.
5. При регрессии остановить следующий выпуск; восстановить подтверждённый Pages-reserve в рамках разрешённого отката и записать результат. Не откатывать чужие новые commits force-push без проверки.
6. Сохранить RESULT, state и новые DECISIONS в Git. Обновить канонический указатель если рабочая ветка изменена. Кратко сообщить URL, что сделано и что фактически проверено.
