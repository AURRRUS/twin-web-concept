# Twin — начать здесь

1. Прочитать `AGENTS.md` и `.twin/START.md`.
2. Открыть единственный реестр `.twin/state.json`. Из него получить текущую рабочую ветку, workflow-задачу, site candidate и раздельные сведения V1/V2.
3. Сверить реестр с фактическим Git/remote и открыть TASK, task.json, RESULT/HANDOFF соответствующей задачи. Не запускать визуальную задачу при инфраструктурном scope.
4. Для V2 продолжить через `V2_START.md`; бренд, каноны и опубликованную версию не угадывать по старому main или названию ветки.

Если начальная ссылка ведёт на историческую ветку, использовать явно переданную владельцем рабочую ветку и сравнить более свежие изменения до исполнения. Локальные и удалённые исходники доступны через соответствующие Git-инструменты; отсутствие clone само по себе не означает отсутствие доступа.
