# Сайт Twin V2 — вход
Обновлено: 27.10.2026. Первые два экрана опубликованы, визуальные дефекты зафиксированы; полного сайта V2 ещё нет.

Рабочая ветка V2: **work/twin-v2**. Каноническая V1 остаётся work/twin-site-system. Не следовать старому canonicalBranch вслепую для задач V2.

1. Читать AGENTS.md, .twin/START.md, .twin/ROUTING.md и этот файл.
2. Читать .twin/v2/project.json, docs/v2/DECISIONS.md и docs/v2/MASTER.md.
3. Первый исполнимый контракт: .twin/tasks/VIS-002/task.json и TASK.md. PROMPT.txt можно передавать текстом.
4. Открыть ВСЕ три изображения docs/v2/references. Для Journey приоритет у journey-white-bronze.jpg. Общие изображения содержат отменённые тексты/детали — сверять DECISIONS и content.json.
5. Реальные навыки .agents/skills/frontend-engineer, ui-ux-pro-max, code-motion, design-review + их PROJECT_OVERRIDE. Они уже в этой ветке. Отдельных AI-агентов автоматически не вызывать.
6. Порядок производства: контекст и проверка ассетов → статичная связка первого и второго экранов → адаптив → motion → браузерное исправление → отдельная публикация /v2/ → RESULT и HANDOFF в Git.

Оригинальные ассеты находятся в репозитории. Референсы из ImageGen нельзя использовать одной картинкой вместо сайта. Код должен оставаться редактируемым ChatGPT и Codex.

## Обязательный контроль качества
Читать docs/v2/QUALITY.md. Перед выпуском quality:v2 проверяет свежесть визуального разбора и evidence; status blocked означает не публиковать очередной вариант как готовый. Текущий выпуск остаётся доступен. Задача исправления — H1, архитектурный переход, пропорции Journey. Не придумывать PASS и не удалять gate ради выпуска. Продолжение всего сайта требует полного scope, не нового скрытого ограничения двумя экранами.
