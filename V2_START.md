# Twin V2 — вход

Текущие указатели находятся только в `.twin/state.json`. `workflowTask` — выполняемая инфраструктурная работа, `siteCandidate` — последняя визуальная реализация; это разные назначения. `profiles.v2.published` — отдельно записанная публикация с областью проверки, а не обещание, что текущая ветка уже видна онлайн. V1 хранится отдельным профилем.

1. Прочитать `AGENTS.md`, `.twin/START.md`, реестр и `.twin/ROUTING.md`.
2. Открыть TASK/task.json/RESULT/HANDOFF задачи из `workflowTask.path` и визуальные TASK/contract/REVIEW из `siteCandidate.path`. Если RESULT/HANDOFF ещё отсутствуют, задача не считается законченной. Проверить scope последней команды.
3. Прочитать `docs/v2/DECISIONS.md` и `docs/v2/MASTER.md`. Исторические VIS-пакеты описывают свои версии; не исполнять их целиком автоматически.
4. Унаследовать типографику и бренд из `.twin/tasks/VIS-004/ENGINEERING.md`; актуальные числовые роли и наблюдаемые отклонения — канон по `profiles.v2.typographySource`. Референсы и исходные изображения брать из действующей задачи. Обзорные изображения могут содержать отменённые тексты и детали.
5. Применить Web Production как координатора, Frontend Engineer как инженера и Twin Site как проектный адаптер. Настоящие отдельные агенты и проверки требуются по актуальному scope, а не подразумеваются наличием SKILL.md.

## Продолжение и приёмка
Открытые дефекты candidate перечислены в реестре и подтверждаются его REVIEW. Их нельзя закрыть старым глобальным visual-review или техническим PASS. Подробности качества — `docs/v2/QUALITY.md`; workflow — `docs/v2/PRODUCTION_WORKFLOW.md`.
Выполнять только текущее задание. Для визуальной работы: статика → адаптив → motion → реальный браузерный проход и исправления. Полный рендер не заменяет сайт, DOM-текст и органы управления. Сохранить source/version и проверенные состояния.
Разрешение публикации читать по `publicationAuthority.source`. Рабочий preview с зафиксированным дефектом отличается от финально принятого сайта. Во время задачи настройки workflow выпуск не выполняется. Разрешённый V2 выпуск затрагивает только `/v2/`, сохраняя V1.
