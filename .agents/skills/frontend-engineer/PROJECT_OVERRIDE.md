# Приоритет проекта Twin
Прочитать `.twin/DESIGN.md`, `.twin/tokens.json`, `.twin/DECISIONS.md` и `.twin/ROUTING.md` из корня репозитория. Они выше дефолтных тем, примеров, шрифтов и внешних DESIGN.md навыка. Не устанавливать инструменты и не приписывать отсутствующие навыки. Относительные ресурсы самого навыка разрешать от его папки. Чтение навыка не равно вызову отдельного агента.

## V2 и перенос референсов
Для work/twin-v2 читать V2_START.md, docs/v2/DECISIONS.md, docs/v2/MASTER.md, .twin/v2/tokens.json и реальные ассеты V2. V1 канон не переносить поверх новых решений.
Режим текущей задачи владельца — обновление frontend-инструментария, не запуск переделки сайта. Новую реализацию начинать по отдельной задаче.
Для reproduce/redesign обязательно references/reference-to-code.md, visual-task.md и visual-review.md. Главные референсы уже в docs/v2/references; до конкретного задания определить последний выбранный кадр и состояние. Числа текущих токенов — исходная система, не доказательство одобрения владельцем. Нельзя менять их ради вкуса; требуемые уточнения записывать в канон с источником.
