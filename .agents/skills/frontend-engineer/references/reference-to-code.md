# ImageGen → работающий интерфейс

## Цель и полномочия
Выбрать конкретное изображение и состояние, записать путь, размер, принятую владельцем часть и последние изменения. Overview всей страницы задаёт направление; локальный экран — композицию блока; действующие тексты и бренд — факты. Сначала увидеть изображение. Отсутствующее содержимое не выдумывать.
Различать polish (сохранить композицию), redesign (заменить композицию), reproduce (воспроизвести выбранный макет). Нельзя выполнить redesign только заменой цветов старых компонентов. Переиспользовать данные и поведение, но менять DOM/CSS под целевую композицию.

## Измеримый макет
На выбранном viewport для каждой смысловой группы определить x/y/width/height относительно секции, общие направляющие и порядок чтения. Значения с изображения помечать measured-estimate, требования владельца — owner, инженерные решения — proposed. Координаты служат контрольными якорями; весь сайт не нужно absolutely позиционировать.
Указать контейнер, поля, колонки, gap, выравнивание и поведение между breakpoint. Разделить внешний отступ секции и внутренний контейнер. Медиа-колонки: minmax(0, …), текст: min-width:0. Не лечить overflow глобальным clip/hidden — найти источник.
Для каждой текстовой роли указать файл/оси, числовой weight, size px, line-height px, tracking px/em, max-width и смысловые переносы. Указать desktop/low-laptop/mobile значения. Текст оставлять DOM. Не имитировать начертание scaleX, text-stroke или синтетическим bold. Не уменьшать целиком сцену из-за переполнения.
Сопоставить видимый bounding box объекта внутри PNG с рамкой img: прозрачные поля делают объект маленьким при формально правильной ширине элемента.

## Технология каждого слоя
| Слой | Реализация | Параметры |
|---|---|---|
| Текст, кнопки, раскрытие, формы | DOM + Grid/Flex | поток, состояния, reflow, focus |
| Геометрия, линии, маска, связи | CSS/SVG | viewBox, координаты, толщина, слои |
| Фото, зерно, сложная поверхность, архитектурная грань | исходный/подготовленный raster | путь, alpha, разрешение, crop, focal point |
| Интерактивная модель | существующий viewer/WebGL | реальный API или честный demo |
| Простая поверхность и глубина панели | CSS | цвет, граница, градиент, inset/ambient/contact shadow |

Разделять мягкую окружающую тень и короткую контактную, выбирать значения по референсу и сохранять токенами. Пример синтаксиса, не канон: box-shadow:0 2px 5px rgb(30 25 20 / .06),0 22px 50px rgb(70 45 20 / .12). Не назначать всем блокам одинаковую тень.
Для фото указать aspect-ratio, contain/cover и object-position. План и интерфейс не обрезать ради заполнения. Проверять видимый размер содержимого, а не только рамку.
Не заменять фотографическую грань диагональным div или ступенчатой маской и не называть это соответствием. Подготовить недостающий слой при авторизации и наличии инструмента; иначе отметить конкретный незавершённый приём. Не запекать функциональный интерфейс и целую страницу в растр.

## Реализация
Собрать статичное состояние с настоящими текстами и ассетами, сравнить массу, интервалы и точку входа на том же viewport. Исправлять крупнейшее расхождение первым. Затем адаптив и motion. При заказе полной страницы пройти все разделы; локальная проверка не сокращает scope до одного экрана.
Сохранять routes и данные; старый layout не обязан сохраняться при redesign. Один владелец геометрии на компонент, без бесконечных overrides. Анимация не должна скрывать плохую статичную композицию.
