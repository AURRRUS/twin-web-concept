# Производство слоёв для web
Читать перед реализацией художественного приёма, которому не хватает материала. Полный mockup — спецификация композиции; он не заменяет набор production assets.

## Что рисовать отдельно
Не генерировать заново всё для каждого блока. Сначала инвентаризировать оригиналы.
Состав комплекта определить самостоятельно по принятой сцене, состояниям и движению. До серийного производства пройти пробу одного сложного образца по [контракту команды](production-contract.md); согласование общей композиции не означает автоматического согласования качества всей серии.
- CSS/SVG: простые плоскости, бронзовые панели, линии, рамки, базовые тени, схемы, контуры, маски. Тексты и controls — DOM
- Raster: сложная архитектурная грань, фотографический вырезанный объект, световой/фактурный pass, сложная материальная поверхность
- Отдельный UI поверх экрана устройства: DOM/SVG или точный исходный screenshot с утверждённым содержимым; не генеративный мелкий текст
- Параллакс: background clean plate + midground/foreground с alpha. Простое вырезание здания оставляет дыру — восстановить перекрытую область и проверить траекторию

## До генерации или извлечения
На каждый asset зафиксировать:
id, роль, parentScene, source, referenceFrame, status (existing / needs-extraction / needs-generation / ready), medium, targetCSSSize, exportPixels, alpha, crop/focalPoint, visibleBounds, anchor, zOrder, motionRange, mobileVariant, shadowMode, safeTextArea.
Размер экспорта считать по максимальному CSS-размеру × выбранному DPR × максимальному scale. Не обещать разрешение, не поддерживаемое генератором; измерить полученный файл.
Один координатный холст для совмещаемых passes: одинаковые camera/crop/размер/anchor/свет. Сохранять padding достаточный для движения; не tight-crop каждый слой независимо. В manifest хранить экспортный bbox и положение видимого объекта.
Определить, входит ли тень в alpha: baked shadow двигается вместе с объектом; отдельная shadow-layer синхронизируется. Двойная CSS+raster тень допустима только как осознанная комбинация contact/ambient.

## Задание imagegen на слой
Передать выбранный визуальный reference и исходники; указать только требуемый слой, камеру, свет, пропорции, поля движения и места стыка. Для cutout запросить прозрачный фон штатным параметром, без надписей/логотипов/кнопок. Для clean plate описать восстановление фона после удаления foreground. Не требовать генератором точную вставку бренда и точный DOM-текст.
Осмотреть результат перед следующей генерацией: геометрия объекта, alpha без белого ореола, стык, отсутствие дублированных деталей. При реальной архитектуре сохранить ограничения исходника; не дорисовывать скрытые конструкции как факт.
Хранить objectLock и исходную версию: защищённые составляющие проверять при каждом усилении. Указывать предел вызовов и использованные попытки; сохранять исходник и лучший вариант. Для skip необязательного слоя записать причину и scope. Статусы prepared/ready/accepted не смешивать: принятие в сцене делает FE.
Не масштабировать готовую страницу-растр до огромного размера и не называть это extraction. Не генерировать весь пакет до выбора композиции. При достаточном исходнике предпочитать извлечение, если разрешён подходящий инструмент.

## Контактный лист и проверка сборки
Собрать preview слоёв на общем холсте при p=0/.5/1, а также reverse и экстремальных смещениях. Preview может быть кодовым; это не дополнительный концепт для согласования.
Проверить силуэт, seam, alpha на светлом и тёмном фоне, crop, читабельность зон текста, совпадение теней, отсутствие дыр на всей траектории и mobile. После этого статус ready и реальные пути в manifest.
Если материалов нет, сохранять незавершённый asset явно. Не упрощать ключевой визуал молча и не писать ready-for-owner-review при отсутствующем ключевом слое.
