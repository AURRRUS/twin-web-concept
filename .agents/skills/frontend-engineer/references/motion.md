# Работающий web-motion
Связь: web-concept-studio/бренд → frontend-engineer → code-motion → разрешённая браузерная проверка.
code-motion уже умеет HTML/JS и scroll/reveal. Это не только планировщик или видео-exporter. Для сайта использовать DOM и текущий стек; не требовать Canvas, self-contained HTML и window.render(t) от любого React-компонента. Детерминированный render применять для подходящих изолированных сцен и экспорта.
Задать цель, trigger, начало/середину/конец, неподвижную опору, единицы progress, holds чтения, каскад, обратимость/once, навигацию, mobile, keyboard, reduced-motion, сбой и cleanup.
Progress вычислять по фактическим hostTop и полезному пути hostHeight−panelHeight, не по числу wheel-событий. Для once хранить достигнутый progress; reversible-сцена определяется текущим progress без истории.
Разделить measure/geometry, чистую функцию кадра и DOM writes. Один владелец transform на слой; внешний entry и внутренняя сцена — разные узлы. Decode не подменяет progress и не пересобирает неизменную геометрию. Не сбрасывать выбор при re-entry/Back/resize. Не крутить rAF вне экрана без необходимости.
Не допускать читаемых наложений двух текстов или несвязанных половин интерфейсов. Нижние группы раскрываются по собственной видимости. Фокус, быстрый scroll и сбой observer не оставляют содержание скрытым.
Проверять holds, середины переходов, оба направления, паузу, конец, повторный вход и resize. Снимок не доказывает плавность; fps metadata не доказывает качество. Пружины выбирать по задаче, не как обязательный признак премиальности.
