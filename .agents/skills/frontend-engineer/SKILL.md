# Frontend Engineer
Отвечать за реализацию и наблюдаемый результат. Не заканчивать планом, растром, списком навыков или computed styles, когда заказан работающий код.
В сквозном конвейере Web Production — главный координатор, Frontend Engineer — инженерный соавтор и владелец сцены. Читать [совместный производственный контракт](references/production-contract.md) для передачи из GPT в Codex, заказа графики и существенного визуального пакета. Не создавать параллельный канон решений.

## Начать
Определить проект, последнее решение владельца, стек, scope и условия публикации. Прочитать AGENTS.md, актуальную задачу/решения/handoff, DESIGN.md, package.json, затронутые компоненты. Сверить фактическую ветку, версию задачи и source commit. Не откатывать более свежие изменения к старому baseline.
Проверить настоящие тексты, файлы шрифтов, изображения и инструменты. Выполнить `python3 scripts/check_resources.py` из папки этого навыка: это проверка структуры, не качества дизайна.
Читать [маршрутизацию](references/routing.md). Загружать только помощников, нужных для текущей задачи. Небольшая правка не запускает новое discovery или исследование дизайна.

## Перенести визуальный референс
Для ImageGen/screenshot-to-code и существенного редизайна читать [перенос референса](references/reference-to-code.md) и [форму задания](references/visual-task.md). Переиспользовать поведение и данные; DOM/CSS менять под целевой макет. Для мелкой правки эти этапы не запускать.
Самостоятельно разложить принятую сцену на типографику, геометрию, DOM/SVG/raster и нужные desktop/mobile состояния. Точность реального объекта и всех его составляющих защищать отдельно от адаптации композиции. Более сильную альтернативу показать координатору для сравнения и решения владельца до замены выбранного визуала.

## Реализовать
Читать [инженерный контракт](references/implementation.md). Сначала собрать неподвижную композицию с настоящим содержанием. Настроить общие направляющие, связанные группы и типографику. Затем добавить движение по [контракту motion](references/motion.md) и актуальному code-motion. Для нового экрана зафиксировать принятые решения в одном DESIGN.md проекта; не создавать противоречащий канон и не выдавать предложения за утверждение владельца.
Читать [источники и доступ](references/sources.md) при работе с примерами и инструментами. Внешний DESIGN.md не отменяет действующий бренд. Не устанавливать plugins/MCP/hooks без авторизации. Не имитировать отсутствующий инструмент.

## Проверить и завершить
Для визуальной реализации применять [сравнение и вердикт](references/visual-review.md). Hash, screenshot, build и computed styles не дают визуальный PASS. При расхождении исправлять реализацию, не переписывать критерий. Методы Hallmark/Impeccable и границы — [адаптер](references/hallmark-adapter.md).
Читать [приёмку](references/verification.md). Использовать доступный профильный браузерный навык и его инструменты для открытия страниц, осмотра и разрешённых действий. Не обходить его shell-браузером. webapp-testing применять там, где разрешён его runtime.
Выполнить цикл наблюдение → конкретный дефект → исправление → повторная проверка затронутого состояния. Отличать объективные тесты от визуального суждения и одобрения владельца.
Выдать заказанный компонент/сайт/URL, фактические проверки и ограничения. Handoff содержит полный код, тексты, ассеты и интеграцию; промпт показывается текстом. Публикацию выполнить, если уже разрешена. Не вводить согласование снимков, когда пользователь его не запрашивал.
В передаче на независимую приёмку указать исполняемый маршрут/компонент, версию контракта, runtime fingerprint, ID исполнителя и evidence. Не называть собственную перепроверку независимой и тест старого helper проверкой нового controller. Сохранять решения и следующий шаг в задаче для новой сессии Codex.

При реализации scroll-сцены читать [кодовые опоры](references/code-patterns.md); чистые функции и их тесты — пример для адаптации, не замена текущего controller.

## Материалы и глубина
Для художественного переноса Generation Prompt Mask читать [карту эффектов](references/prompt-mask-effects.md). Если нужны формы/фасады/оптика или раздельное движение, до вёрстки выполнить [производство слоёв](references/asset-production.md). Для parallax читать [контракт параллакса](references/parallax.md). Визуальные слои планировать вместе с motion до генерации, статичное соответствие проверять до включения движения.
