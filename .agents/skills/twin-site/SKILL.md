# Сайт Twin
1. Определить режим: подготовить ТЗ / выполнить / проверить. Не выполнять pendingTask при просьбе собрать систему или просто назвать проект.
2. Найти `AURRRUS/twin-web-concept`. Прочитать `main/TWIN_START.md` и `main/.twin/project.json` через доступный GitHub, получить canonicalBranch. Если локальная актуальная копия уже есть, читать её AGENTS.md и `.twin/START.md`. Отсутствие локального clone не равно отсутствию GitHub.
3. Резервный указатель при установке — `work/twin-site-system`. Более свежий указатель репозитория выше этого снимка. Не писать сайт в старый main starter и не откатывать свежие изменения.
4. Читать `.twin/DECISIONS.md`, DESIGN.md, ROUTING.md. Составить задачу по TASK_TEMPLATE из обычной правки самостоятельно; числа брать из tokens.json, файлы — assets.json. Не требовать от владельца CSS-спецификацию.
5. Ведущий навык — `.agents/skills/frontend-engineer/SKILL.md`; нужные помощники определены ROUTING. Читать реальные файлы и PROJECT_OVERRIDE; не имитировать отсутствующий навык или отдельно вызванного агента.
6. Подготовка: заполнить контракт, валидировать, сохранить в Git, показать полный PROMPT.txt прямо текстом. Исполнение: статичная композиция → адаптив → motion → браузерная проверка и исправления → разрешённая публикация → RESULT и память в Git.
7. В конце заголовков точки запрещены. Новая типографика Journey — RF Dewi; бренд ПИН не переносить. Последнее явное решение владельца выше старой документации; записать его с источником.
8. Не вводить согласование скриншотов перед уже разрешённым выпуском. Не выдавать build/computed styles за визуальный PASS. Если инструмент недоступен, назвать непроверенное. Сохранение только в чате не является памятью проекта.
