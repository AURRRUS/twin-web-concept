# Графика Twin — проектные уточнения

Общая [маршрутизация графики](../../web-production/references/image-routing.md) принадлежит Web Production. Для Twin Frontend Engineer заказывает конкретные layers, выбирает исходный master/crop/anchor/alpha и принимает пригодность в сцене. Простые линии, панели, геометрию и тени делает CSS/SVG без генерации.

Реальная архитектура, пропорции и составляющие объекта защищены. Для фотографической архитектуры выбирать доступный TALENT photorealism; для целевого cutout/mask — доступный imagegen с точным контрактом слоя. Многопроходное или фрагментное усиление назначается под видимый дефект и реальный масштаб, с конкретным бюджетом, проверкой между попытками и сохранением исходника/лучшей версии. Части изображения и проходы — разные вещи.

Прежде серии согласовать представительный сложный образец в контексте desktop/mobile. Из общего пожелания качества не следует разрешение на неограниченные вызовы. Уже принятую авторизацию конкретного job не запрашивать заново. Полный выбранный графический навык и его обязательные references читать перед исполнением.

Методы PIN ImageGen, если применимы по решению владельца, не переносят бренд ПИН, кристаллы, палитру или логотипы в Twin. У реального объекта нельзя придумывать скрытые детали как достоверные. Новая C принимается только после сопоставимого сравнения с лучшей B; число проходов само по себе не доказывает качество.
