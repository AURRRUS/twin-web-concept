# Производство Twin: единый координатор
Команда «Сайт Twin — производство» запускает этот workflow до запрошенного результата в пределах авторизации. Для подготовки системы не запускать автоматически сайт или дорогую генерацию.
Координатор — twin-site. Это роль главного исполняющего агента, не отдельный постоянно работающий сервер. product-creative-producer отвечает за незакрытые продуктовые решения, не за маршрутизацию каждого CSS-отступа.

## Один запуск, одна память
Хранить в папке задачи TASK.md, content.json, visual-contract.json, asset-jobs.json, review.json, RESULT.md и run.json. Переиспользовать существующие файлы, не плодить дубли. Координатор читает последний статус и продолжает с первого незакрытого обязательства. Учитывать фактический source commit и версии файлов; старый review после изменений не действителен.
Вход: задача владельца, выбранный reference, версия сайта, scope, допустимые изменения, публикация. Недостающие инженерные числа выбирает фронтендер и помечает источник; не перекладывать их на владельца.

## Ответственные и выходы
| Этап | Ответственный | Вход | Проверяемый выход и возврат |
|---|---|---|---|
| Цель и выбранная композиция | Web Concept Studio; producer только при смысловой развилке | задача, бренд, содержание | reference + content lock + ключевые визуальные отношения; при неясности вернуть сюда |
| Разбор реализуемости | Frontend Engineer + Code Motion | reference, код, оригиналы | сетка/числовая типографика/слои/адаптив/фазы; список недостающих ассетов |
| Производство графики | графический исполнитель по image-routing.md | asset job | файлы, реальные размеры, alpha/стыки/до-после; непригодный материал вернуть исполнителю |
| Кодовая сборка | Frontend Engineer / Codex | контракт и пригодные ассеты | статичная композиция → адаптив → рабочий motion; CSS/SVG делает фронтендер |
| Приёмка материала | Frontend Engineer как заказчик | графические outputs | пригодность crop/scale/anchor/alpha в сцене, а не только красота картинки |
| Визуальная приёмка сайта | Design Review отдельным проходом | reference + браузерные кадры + критерии, без оправданий автора | recapture/rebuild/fix/ready-for-owner-review; конкретные дефекты и маршрут возврата |
| Функции и выпуск | frontend + координатор | актуальный код и review | обычный scroll до footer, keyboard/mobile/reduced-motion, публикация по разрешению, точная версия/ограничения |

## Что обязан спросить ответственный у своей работы
Фронтендер: совпадают ли масса/направляющие/поля; какой layer отсутствует; достаточно ли нативного разрешения; почему нужна генерация, а не CSS/SVG; не сохранил ли старый layout вопреки redesign?
Графический исполнитель: что защищено; какая камера/геометрия; какой холст/alpha/overscan; какие границы должны совпасть; действительно ли улучшилась детализация при одинаковом масштабе?
Design Review: та ли композиция; что замечает человек первым; сколько типографических ролей предусмотрено и где необъяснимые отклонения; каков видимый размер объекта без прозрачных полей; где читаемый текст/CTA потерян; есть ли пустой экран?
Координатор: каждый ли блок имеет ответственного и выход; какой именно дефект мешает следующему этапу; нет ли повторного дорогого прогона без новой гипотезы; не объявлен ли self-review независимой проверкой?

## Заказ на графику
Каждый job: id, scene, requester, producerSkill, purpose, sourcePaths, reference, protected, operation, targetCSSSize, targetPixels, alpha, anchor, crop, overscan, shadowMode, qualityReason, maxCalls, attemptsUsed, outputs, status, acceptedBy, observed.
Для простой панели/линии producerSkill=frontend-engineer, operation=css-svg, maxCalls=0. Для фото выбирать маршрут image-routing.md. Не отправлять imagegen задачу рисовать DOM-текст, реальные шрифты или всю страницу вместо editable code.
До исполнения убедиться в доступности генератора/файлов и авторизации. Если Codex не имеет генератора, оставить job blocked с конкретным отсутствующим инструментом; координатор исполняет его здесь доступным imagegen и передаёт реальный файл. Не имитировать удалённый вызов навыка.
accepted означает пригодность под scene, а не одобрение владельцем. При деградации сохранить лучшую версию, вернуть job с причиной. Не увеличивать бюджет скрытно.

## Возвраты
Плохая композиция → frontend или Web Concept Studio, не повторный апскейл.
Маленький видимый объект → frontend проверяет рамку/crop/alpha padding до генерации.
Мыло при фактическом масштабе → графический job, метод выбирается по причине.
Шов/alpha/двойной объект → графический исполнитель и проверка сборки слоёв.
15 размеров без роли → frontend исправляет систему ролей и канонический CSS, не ручные patches каждой надписи.
Scroll trap/двоение текста → frontend + code-motion; проверка обоих направлений и выхода.
После двух безрезультатных итераций координатор меняет диагностическую гипотезу, не запускает тот же цикл.

## Автоматизация и честные границы
Агент-координатор последовательно выполняет стадии через инструменты среды; читает нужные навыки, сам составляет asset jobs и промпт Codex, сохраняет статусы и исправления. Пользователь не обязан пересылать задания между воображаемыми сотрудниками.
scripts/production_next.py вычисляет первый блокер и следующего ответственного из run.json. Он не запускает модели, ImageGen, Codex или браузер и не определяет красоту. Автономный фоновый dispatcher/API runner этим навыком не установлен.
Настоящий независимый reviewer — только отдельный доступный агент/процесс с чистыми входами. При отсутствии — статус self-review/not-independent; не представлять его как независимую приёмку. Выпуск по действующей авторизации и проверкам, без нового обязательного согласования снимков.

## Машинный статус
Скопировать references/run-template.json в папку задачи. Команда: python3 <skill-root>/scripts/production_next.py <task>/run.json <project-root>. stages хранит status/evidence, assetJobs — заказы, review — runtime/reference/verdict/unresolved и независимость. mode=prepare не разрешает исполнение. Ответ скрипта — маршрутизация обязательств, не команда публикации. Этапы без применимых изменений закрывать существующими свежими доказательствами и явным основанием, не фиктивной работой.
