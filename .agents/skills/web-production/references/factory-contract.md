# Единый контракт Web Production ↔ Frontend Engineer

Версия 1 · решения владельца 29.10.2026. Применять к конвейеру; для локального исправления использовать только затронутые обязательства. Не запускать производство сайта или графики по запросу аудита процесса.

## Владение результатом
Web Production ведёт цель, конверсионную логику, зависимости, решения оператора, актуальный пакет задачи, бюджет производства и возврат дефектов. Frontend Engineer переводит замысел в измеримую композицию, самостоятельно определяет части и заказывает графику, принимает её в сцене, реализует адаптив и движение. Он обязан возвращать координатору неясный контракт или непригодный материал до массового кода.
Web Concept Studio предлагает композицию; PIN Web Concept System — её брендовый слой только для PIN; Code Motion помогает проектировать и исполнять движение. Графический исполнитель создаёт конкретные файлы. Независимый reviewer проверяет реализацию; финальный результат утверждает оператор после проверки команды. Один человек/агент может выполнять несколько совместимых функций, но автор не становится независимым проверяющим своей работы.
Навык — инструкция; отдельный агент — фактически запущенный поток с ID, входом, заданием и результатом. GPT руководит с оператором, Codex организует исполнителей и отдельного проверяющего в своей доступной среде. Автоматическая связь между двумя чатами не подразумевается.

## Профили и инварианты
Универсальное ядро отлаживать на Twin и PIN; клиентский проект получает собственные бренд, контент, источники и бюджет. Не объединять их сайты, репозитории и дизайн-токены ради общей методики.

| Профиль | Приоритеты при конфликте |
|---|---|
| PIN | Качественная мобильная версия и скорость загрузки; затем точность композиции и эффектность. При проектировании сразу сделать mobile сцену и оценить стоимость медиа. |
| Twin / Talent | Более выразительные сцены и допустимый согласованный расход загрузки; несколько сильных эпизодов. Рабочие CTA, читаемость и выход из сцены сохраняются на mobile. |
| Клиентский девелоперский | По умолчанию mobile и выразительность; лимиты и компромиссы закрепить в профиле проекта до дорогого производства. |

Профили задают приоритет, а не разрешение бесконечной загрузки. Инженер предлагает измеримые лимиты initial media/JS/шрифтов, LCP/CLS/INP и условия замера; координатор закрепляет их до реализации. Отличать лабораторный замер от полевых данных. Старый проектный порядок desktop → mobile не переносить автоматически в PIN.
Точность объекта — отдельный обязательный инвариант всех профилей: архитектура, этажность, фасад, окна, пропорции, планы и реальные составляющие. Не трактовать приоритет эффекта как разрешение их менять. Свет/материалы/окружение улучшать в разрешённых пределах; неизвестные скрытые детали не дорисовывать как достоверные. Responsive-перекомпозиция допустима с сохранением объекта, содержания и согласованной иерархии.

## Контрольные точки оператора
1. **Фундамент:** цель и аудитории, маршрут к действию, содержание/сущности страницы, типографические роли, визуальное направление. Предоставить цельную карту, без заказа оператором каждой детали.
2. **Ключевые сцены:** welcome, решающие конверсионные блоки, самый сложный переход; desktop и mobile. Для сложного motion показать работающую пробу. Можно объединить с пунктом 1, если материал уже готов.
3. **Проба графики перед серией:** один представительный сложный узел в контексте страницы и в нужном масштабе. Согласовать стиль, состав пакета и предел генеративных вызовов. Оператор не обязан утверждать каждый cutout.
4. **Финал:** результат после технической и независимой визуальной проверки. Разрешённый рабочий preview можно выпускать раньше с явными дефектами; не называть его окончательно принятым.

Для каждой точки сохранить, что именно утверждено, ссылку на артефакт/версию и решение оператора. Ранее полученное решение использовать повторно, пока утверждённый предмет не изменился. Отказ от отдельной точки допустим по уже данному решению оператора или для явно не затронутого предмета; не выдумывать одобрение.
Если команда видит лучшее решение, подготовить сопоставимые A/B кадры или прототипы, объяснить механику, влияние на конверсию/mobile/стоимость. Внедрять альтернативу после выбора. Внутренние измерения, размеры масок, экспорт, исправление дефекта в рамках контракта команда решает сама.

## Общий интерфейс передачи
Хранить данные в существующих проектных файлах; новые имена не обязательны. У каждого решения один канонический источник.

| Передача | Минимальный проверяемый выход |
|---|---|
| Координатор → FE | task ID, цель/CTA, scope, актуальная версия, источник бренда/контента, выбранные reference/state, утверждения, ограничения, критерии |
| FE → графика | scene/asset ID, неизменяемый объект, исходник, общий холст/camera/anchor, размеры/видимые границы, alpha/mask/overscan, desktop/mobile, количество и цель проходов |
| Графика → FE | реальные пути и размеры, версия/происхождение, слои и края, лучший выбранный вариант, результат сравнения; подготовленное изображение ещё требует проверки в сцене |
| FE → Codex | visual-contract, scene/asset manifest, storyboard/scroll-бюджет, готовые материалы или точный missing job, реализация/приёмка/границы |
| Codex → reviewer | фактический candidate, reference/contract, браузерный доступ, состояния/матрица; без авторских оправданий и готового положительного вердикта |
| Reviewer → координатор | наблюдаемые дефекты и серьёзность, evidence, версия, независимость, технический и визуальный вердикты раздельно |
| Координатор → оператор | доступный результат, существенные отличия, открытые дефекты, конкретный предмет выбора/приёмки |

## Графика и темп
Полный разбор сцены выполнять до серийной генерации. Делить по функции и движению, а не механически на прямоугольники. Сначала оригиналы и CSS/SVG, затем нужные raster layers. Проверять сборку до motion и при крайних состояниях.
Крупный визуал оценивать в его максимальном реальном размере. Многопроходное усиление назначать по видимому дефекту/требуемой детализации; число проходов само по себе не доказывает качество. Сохранять исходник и лучший вариант; новая итерация может быть хуже. После двух неулучшающих попыток остановить повторение, изменить диагностику и показать проблему. У каждого заказа есть maxCalls, attemptsUsed, условия остановки; отсутствие ограничения по времени не означает бесконечную генерацию.
Каждой эффектной сцене назначать смысл, решение пользователя и следующий CTA. FE с Code Motion рассчитывает путь скролла, диапазоны раскрытия/удержания/выхода, обратный ход и mobile fallback; Web Production проверяет общий темп до footer. Огромный путь без нового смысла — дефект. Не перехватывать скорость физического скролла ради сценария: ускорение/замедление визуала задавать отображением progress, с доступным выходом.
Конверсионный маршрут и события можно спроектировать и проверить; рост конверсии не утверждать без реальных данных.
