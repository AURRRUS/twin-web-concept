# Графическая маршрутизация
Проверено по реальным навыкам 27.10.2026. Метод ≠ бренд ≠ число частей.

| Задача | Исполнитель | Режим |
|---|---|---|
| Картинка/слайд бренда ПИН | pin-imagegen | оригинальные логотипы/профиль ПИН, обычный фотографический режим — один проход |
| Архитектура Twin/Talent | talent-photorealism + штатный imagegen | обычный один проход, профиль Twin; не переносить ПИН |
| Нефотографическая маска/cutout/сложная форма | штатный imagegen с контрактом слоя | alpha/камера/свет/стык; не фотографический апскейл по умолчанию |
| Детализация большого изображения по 3–4 перекрывающимся частям | tiled-photorealism | части, соседние стыки, сборка, лучшие версии; 3 части не означают 3 прохода |
| Контекстный полный апскейл TALENT | talent-photorealism/full-upscale | 2 или 3 прохода; требует отдельного согласования конкретного объёма по этому навыку |
| Линия/панель/треугольник/простая тень | frontend-engineer | CSS/SVG, генеративных вызовов 0 |

В текущем pin-imagegen НЕТ автоматически включаемого тройного режима: photorealism.md прямо запрещает самовольный tiled/full upscale. Общую просьбу «максимальное качество» не превращать в дорогое усиление. Если конкретный режим уже разрешён для этого job — не спрашивать повторно. Обновление workflow не является заказом обработки всех изображений.
При прямом разрешении заимствовать фотографический метод между проектами переносить только метод, не фирменные кристаллы/палитру/логотипы/правила бренда. Для фотографической архитектуры прямой маршрут TALENT точнее и короче.
Источник S и лучшая принятая B неизменны; C принимается только после сравнения при одинаковом масштабе, проверки геометрии/света/детализации/alpha. Native размеры и export resize указывать отдельно. Не делать full enhancement перед подтверждением композиции.
При реальном запуске читать полный выбранный навык и его обязательные references. Эта таблица не заменяет промпт и процедуру обработки.
Перед серией применять контрольный образец по [контракту команды](factory-contract.md): один сложный слой/стык в контексте desktop/mobile, затем подтверждение направления и согласованный объём. У objectLock отдельный список неизменяемых составляющих и источник. Выбирать 2/3 прохода с планом реальных вызовов/фрагментов, а не считать «тройной» тремя картинками. Разрешённый пользователем конкретный бюджет повторно не согласовывать.
